    Windows Privilege Escalation Guide

    Foundational Security Concepts

    Essential Background Knowledge

    Understanding these concepts is critical before attempting any privilege escalation attacks. These explain the "why" behind the techniques.

    Understanding Security Identifiers (SID)

    Windows uses SIDs rather than usernames for all security decisions. Each user and group has a unique SID that defines their security context.

    Your objective is to obtain an access token associated with a privileged SID.

    Important SID Values

    • S-1-5-...-500: Local Administrator account
    • S-1-5-18: NT AUTHORITY\SYSTEM (highest privilege level - primary target)
    • S-1-5-11: Authenticated Users group
    • RID > 1000: Regular user accounts and custom groups

    Access Tokens & Integrity Levels

    When you authenticate, Windows creates an access token containing your SID, group memberships, and assigned privileges. All processes you launch inherit this token.

    Mandatory Integrity Control (MIC) ranks processes by trustworthiness:

    Level Description
    Low Sandboxed environments (browser tabs, untrusted processes)
    Medium Standard user context - your typical starting point
    High Administrator context - initial escalation target
    System Kernel and critical system services

    Critical Restriction

    Lower integrity processes cannot modify higher integrity objects, regardless of file permissions. Escalation requires moving from Medium → High → System.

    User Account Control (UAC) Mechanism

    UAC splits administrator privileges into two separate tokens:

    • Standard token (Medium integrity) - used by default for routine operations
    • Privileged token (High integrity) - requires UAC prompt approval

    Many privilege escalation techniques focus on bypassing the UAC prompt to access the privileged token without user interaction.

    Initial System Reconnaissance

    Start Here

    Complete this reconnaissance immediately after gaining initial access. Never begin exploitation without this intelligence.

    Primary Objectives

    Map the system landscape, identify user accounts, understand the machine's role, and locate potential attack vectors.

    Current User Context

    Identify your active user and hostname:

    whoami

    Key Information:

    • hostname\username: Current security context
    • hostname: Machine identifier (often reveals purpose: DB-SERVER, WEB-01, DC-PRIMARY)

    Privilege & Group Enumeration

    Determine group memberships and integrity level:

    whoami /groups

    Critical Group Memberships:

    • BUILTIN\Administrators: Full administrative access (rare initially)
    • BUILTIN\Remote Desktop Users: RDP access capability
    • BUILTIN\Backup Operators: Read/write access bypassing ACLs
    • Custom groups: IT-Support, Helpdesk, PowerUsers may have elevated permissions

    Integrity Check: Confirm Mandatory Label\Medium Mandatory Level indicates standard user requiring escalation.

    User & Group Discovery

    Enumerate all accounts to identify high-value targets:

    net user
net localgroup
net localgroup administrators

    Get-LocalUser
Get-LocalGroup

    Target Identification:

    • Administrative accounts: sysadmin, backupadmin, john.admin
    • Administrator group members - highest priority targets
    • Status of default Administrator account (enabled/disabled)

    System Information Gathering

    Extract OS details, architecture, and patch status:

    systeminfo

    Critical Data Points:

    Field Usage Example
    OS Name Version identification Microsoft Windows Server 2019 Standard
    OS Version Exploit matching 10.0.17763 Build 17763
    System Type Payload architecture x64-based PC
    Hotfixes Missing patch analysis Use with windows-exploit-suggester

    Network Configuration Analysis

    Map network topology and active connections:

    ipconfig /all
route print
netstat -ano

    netstat Analysis Points

    • LISTENING: Local services (:3389 RDP, :445 SMB, :5985 WinRM)
    • ESTABLISHED: Active sessions - credentials may be in memory
    • PID: Cross-reference with process names using tasklist

    Application & Service Discovery

    Identify potentially vulnerable software:

    Registry Enumeration (PowerShell):

    # 64-bit applications
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*" | select displayname

# 32-bit applications
Get-ItemProperty "HKLM:\SOFTWARE\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*" | select displayname

    Process Enumeration:

    tasklist /svc

    Get-Process

    Target Applications:

    • Outdated software: Legacy browsers, unpatched utilities
    • Security tools: Password managers (KeePass, LastPass)
    • Development tools: XAMPP, WAMP, local databases
    • Match PIDs from netstat to identify service owners

    Credential Hunting Techniques

    Execution Timing

    Begin after completing initial reconnaissance. Use discovered information (installed software, usernames) to guide your search patterns.

    Mission Objective

    Locate plaintext credentials, API keys, or configuration secrets enabling lateral movement or direct privilege escalation.

    Filesystem Credential Search

    Systematically search for files containing sensitive data, focusing on application directories and user spaces.

    PowerShell Recursive Search:

    Get-ChildItem -Path [START_DIRECTORY] -Include [FILE_TYPES] -File -Recurse -ErrorAction SilentlyContinue

    Parameter Breakdown:

    Parameter Purpose
    -Path Search starting point: C:\, C:\Users\alice\Desktop
    -Include Target patterns: *.txt,*.xml,*.config,*.ini
    -Recurse Traverse all subdirectories
    -ErrorAction SilentlyContinue Suppress access denied errors

    High-Value Locations:

    • User directories: C:\Users\, C:\Users\Public\
    • User data: Desktop, Documents, Downloads folders
    • Application data: C:\Program Files\, C:\ProgramData\
    • Web roots: C:\inetpub\wwwroot\, C:\xampp\htdocs\

    Target File Types:

    Category Examples
    Password Databases *.kdbx, passwords.txt, credentials.txt
    Configuration web.config, app.config, *.ini, database.xml
    Documents *.docx, *.xlsx - onboarding guides, IT procedures
    Scripts *.ps1, *.bat, *.vbs - automation with hardcoded credentials

    Reading Discovered Files:

    type C:\path\to\file.txt

    cat C:\path\to\file.txt

    Credential Exploitation

    Once credentials are discovered, verify the account and determine access methods.

    Validation Process:

    1. Locate credential pair - Example: username: robert / password: P@ssw0rd2024!#

    2. Verify account exists and check permissions:

      net user robert

    3. Determine access method based on group membership:

      Remote Desktop Access (Remote Desktop Users group):

      xfreerdp /v:192.168.1.50 /u:robert /p:'P@ssw0rd2024!#'

      PowerShell Remoting (Remote Management Users group):

      evil-winrm -i 192.168.1.50 -u robert -p 'P@ssw0rd2024!#'

      Local Administrator (no remote access):

      From an existing GUI session, escalate privileges:

      runas /user:adminaccount cmd

      Enter password when prompted for elevated command prompt.

    Iterative Enumeration Cycle

    Critical Concept

    After successfully switching users, restart the entire enumeration process with the new security context.

    Rationale: Different users have different file permissions. Previously inaccessible files may now be readable.

    Real-World Scenario

    User alice received "Access Denied" on database.xml. After RDP access as robert, the file was readable and contained dbadmin credentials, leading to complete system compromise.

    Core Principle

    Every new user context is a new opportunity. Never assume enumeration is complete.

    PowerShell Artifact Analysis

    Timing & Context

    Execute during enumeration after filesystem searches. Administrator PowerShell usage often leaves exploitable artifacts due to poor operational security.

    Strategic Goal

    Extract credentials and sensitive data from PowerShell's persistent logging mechanisms that administrators assume are cleared or invisible.

    PSReadLine History Exploitation

    Target the persistent history file, not the ephemeral session history.

    Common Administrator Misconception

    Get-History only shows current session data. Running Clear-History does NOT remove the persistent file.

    Persistent History Reality: The PSReadLine module maintains a complete command history across sessions and reboots, surviving Clear-History attempts.

    One-Line Extraction:

    type ((Get-PSReadlineOption).HistorySavePath)

    Standard Location

    C:\Users\<username>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt

    High-Value Artifacts:

    • Plaintext credentials: $pass = "MyS3cr3tP@ss", ConvertTo-SecureString "admin123"
    • PSCredential construction: New-Object System.Management.Automation.PSCredential
    • Remote connections: Enter-PSSession, Invoke-Command with inline credentials
    • Transcript activation: Start-Transcript -Path "C:\Logs\session.txt" reveals additional log locations

    PowerShell Transcript Discovery

    Transcripts provide complete session recordings - every command and all output. The ultimate intelligence source.

    Discovery Methods:

    1. Direct reference - Check PSReadLine history for Start-Transcript commands showing exact paths

    2. Filesystem sweep:

      Get-ChildItem -Path C:\ -Include *transcript*.txt -File -Recurse -ErrorAction SilentlyContinue

    Critical Intelligence (Jackpot Scenarios):

    Transcripts capture complete PSCredential object creation that may be sanitized in history files.

    Transcript Gold Mine

    **********************
PS> $secpass = ConvertTo-SecureString "SuperSecure2024!" -AsPlainText -Force
PS> $credential = New-Object System.Management.Automation.PSCredential("adminuser", $secpass)
PS> Enter-PSSession -ComputerName SRV-FILE01 -Credential $credential
**********************

    Result: Direct access to adminuser account with password SuperSecure2024!

    WinRM Credential Exploitation

    Leverage discovered credentials for remote access via Windows Remote Management.

    Detection Indicator

    Presence of Enter-PSSession or Invoke-Command in logs indicates WinRM is active and accessible.

    Tool Selection: evil-winrm from Kali Linux

    Connection Syntax:

    evil-winrm -i <TARGET_IP> -u <USERNAME> -p '<PASSWORD>'

    Practical Example

    evil-winrm -i 10.10.50.100 -u adminuser -p 'SuperSecure2024!'

    Shell Special Character Handling

    Always use single quotes around passwords containing special characters (!, @, #, $, &) to prevent shell interpretation errors on Linux.
